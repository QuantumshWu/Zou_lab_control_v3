# Atom Workbench：频率体系、3D 视图与初态的统一交互设计

本文是界面第二阶段的实现依据。第一阶段（v3 外框、状态条、标签页、Field、用语与格式、tooltip、窄窗口）完成后，在其基础上实现本文内容。

## 0. 总原则

1. **一个选择，处处一致。** 全局只有一个"当前对象"（磁场、激光、参考频率、参考能级之一，或无）。场景面板列表、能级图中的箭头、3D 视图中的箭头都可以选中对象，再点一次已选中的对象即取消选择（回到"无"）；检查器编辑当前对象；三个视图都高亮当前对象。不再有视图内的第二套选择（例如 3D 页的激光标签）。
2. **对象有统一身份色。** 每束激光、每个参考频率有一个颜色，出现在列表图标、能级图中它的跃迁、3D 视图中它的箭头和偏振椭圆上。磁场固定为绿色。颜色来自 token 调色板，不写死。
3. **定义与读数分开。** "这个量是怎么定义的"（会影响物理或会让对象跟随别的对象变化）和"这个量以什么基准、什么单位显示"（纯显示）是两件事，界面上用不同控件、不同位置表达。
4. **单位遵循 v3 规则（与 Device Control 相同）。** 显示出来的（计算得到的）数值换单位时换算：物理量不变，数字随单位改变；操作者在输入框里写下的数值换单位时保留数字：单位真的改变，物理量随之改变（总时长 10 μs 换成 ms 即为 10 ms）。所以输入框换单位是一次真实的参数修改，自动计算像对待任何编辑一样重新求解。新的物理量违反物理约束时（例如光频不再为正），不夹取、不悄悄换算：框中保留新单位下的这些数字并标为无效、写明原因，场景保持原值，直到下一次编辑；Esc 放弃它。同一个量的角色随模式而定：功率与束腰方式下局域强度是计算值（换算），局域强度方式下它是输入（保留数字）。场景保存数值时连同它的单位。显示时不精确的数值写"≈ 四位有效数字"，编辑时保留完整数值；步长按 v3 的 firstStep 规则取最后一位有效数字；换单位后步长重置；不再有"每个单位 ±5000"的伪范围，只保留物理约束（光频 > 0）。

## 1. 频率体系

### 1.1 三类"频率对象"与内置基准

| 类别 | 例 | 来源 |
|---|---|---|
| 内置基准：绝对零点 | ν = 0（即绝对光频） | 固定 |
| 内置基准：零场跃迁 | D2 F=2→F′=3、D1 F=1→F″=2、5P₁/₂ F″→5P₃/₂ F′ | 固定列表（现有 `zeroFieldTransitionOptions`） |
| 激光 | 探测光、repump、光镊 | 场景对象 |
| 参考频率（新） | "冷却光锁频点"、"Rydberg 双光子中心" | 场景对象 |

参考频率是没有强度、偏振、方向的"虚拟激光"，只携带一个频率。它在界面上的行为与激光的频率部分完全一致：可以被选中（能级图显示到它的失谐，但没有耦合强度着色）、可以作为别的频率的基准。

### 1.2 频率表达式（唯一的数据形式）

每个被"定义"的频率（激光频率、参考频率）都是一个表达式：

```ts
type FrequencyBase =
  | {kind:'absolute'}                                   // ν = offset
  | {kind:'transition'} & ZeroFieldTransition           // ν = ν⁰(F→F′) + offset
  | {kind:'reference', id:string}                       // ν = ν(参考频率 id) + offset
  | {kind:'laser', id:string};                          // ν = ν(激光 id) + offset（偏频锁定）
type FrequencyExpr =
  | {base:FrequencyBase; offsetMHz:number}              // 主要形式；offsetMHz 为规范存储
  | {wavelengthNm:number};                              // 只用于"按真空波长定义"的绝对频率
```

- 绝对光频用 `accurateSum` 组合（与现有 `captureLaserFrequencyAnchor` 同样的精度保护），不在 THz 量级上丢失 Hz 级偏移。
- `wavelengthNm` 是"操作者写下的就是波长"，波长输入不被换算成频率存储，避免 852 nm 被写回成 351.86… THz 的十几位小数。
- 频率只以 `frequency: FrequencyExpr` 加它的单位描述（单一真相源）。激光所属 D 线（`line`）不是输入，而是由频率派生的显示属性。

### 1.3 定义行为："锁定"语义

- 激光和参考频率的检查器里，"频率"一行由三部分组成：**数值框**（v3 Field，带单位选择器）+ **"相对"基准选择器**（TreeCombo）。数值框里是相对基准的偏移；基准为"绝对"时数值框里是绝对频率，单位族多出"波长"（nm、μm）。
- **切换基准不改变物理频率**：切换的瞬间按新基准重新计算偏移（与现有 `setLaserTransitionReference` 的语义一致）。
- **之后基准变化时，依赖它的对象跟着变**：例如 repump 定义为"相对 探测光 +6.568 GHz"，探测光改频后 repump 随之移动。这对应实验里的偏频锁定，是有意的语义。依赖关系在检查器中可见（基准行写明"跟随 探测光"），被别人依赖的对象在检查器底部列出"被 repump 跟随"。
- **防环**：基准选择器中不列出直接或间接依赖当前对象的对象；场景文件校验也拒绝环。
- 删除一个被依赖的对象前确认，并把依赖者转换为等效的绝对/零场定义（物理频率不变）。

### 1.4 读数行为："相对…显示"

所有派生出来的频率读数（激光的绝对频率 ν、两态跃迁频率、跃迁矩元表的频率列、能级图标注之外的频率）统一用一个**频率读数控件**：

```
ν₁₂   +6.834 682 610 9 GHz   [GHz ▾]   相对 [绝对 ▾]
```

- 读数用 v3 `Readout`，不可编辑；"≈"规则同上。
- 读数是显示：它的单位选择器和"相对"基准选择器只换算读法，记为该读数位置的显示偏好，存入场景（与其它显示偏好一起），不进入物理请求，也不进入求解缓存键。
- 两态跃迁读数先给出跃迁频率 ν₁₂ 本身，再给出 Δν = ν₁₂ − ν(参考) 和它的"相对"参考（§1.8）。参考的默认值"自动"是这两个态在零场（无磁场、无光移）下的 ν₁₂，所以默认的 Δν 就是磁场和打开"显示光移"的激光让这条跃迁移动的量；也可以选激光、参考频率、零场跃迁或绝对。

### 1.5 能级图标注（保持现有语义）

- **未选中任何对象**：能级位置与标注显示磁场 + 打开"显示光移"的激光带来的移动（总能移）。再点一次已选中的对象（或能级图标题旁光束标签的 ×）即回到这里。
- **选中激光**：该激光的各跃迁按耦合强度着色；每个态标注"该态的跃迁频率 − 激光频率"，正值表示该态更高：激发态 Δ = ν(参考态→e) − ν_L；基态标注相对参考基态的频率 (E_g − E_ref)/h（F=1 在 F=2 参考态之下读 −6.83 GHz）。激光检查器自己的"失谐 Δ"仍是 ν_L − ν(基准)，即激光相对其基准的频率，方向相同。
- **选中参考频率**：同上，但没有耦合强度着色（只有频率，没有强度和偏振）。
- 修正已知的两个 bug：参考能级位于基态范围时参考列的同侧规则；参考态切回真实态时清除过期的"受激辐射"方向标记。
- 图例一行写明当前标注的定义："激发态 ν(参考态→e) − ν(探测光)，基态 (E − E参考)/h；正值表示更高；背景：B + 光镊"。

### 1.6 参考能级（保留，并与频率体系统一）

参考能级是图示用的虚拟能级（不进入动力学）。定义改为：

```ts
interface ReferenceLevel { id; name; anchorId:string; anchorMode:'follow'|'zero-field';
  photon?: {frequency: FrequencyExpr | {object:'laser'|'reference', id:string}; direction:'absorb'|'emit'};
  offsetMHz:number }   // E = E(锚点) ± hν(photon) + h·offset
```

现有的"取激光终点"（一次性把 ±hν_L 抄进 offset）改为可选择**链接**一束激光或参考频率：例如"虚拟中间态 = |2,0⟩ + 一个探测光光子"，探测光改频时它跟着移动。也可以不链接，只写固定偏移。

### 1.7 场景面板结构

```
实验场景
  磁场        [＋]
  激光        [＋]
  参考        [＋▾]  （菜单：参考频率 / 参考能级）
     ν  冷却锁频点     D2 F=2→F′=3 −12 MHz
     E  虚拟中间态     |2,0⟩ + 探测光
  初态
```

参考频率与参考能级同属"图示参考"，不参与物理，列在一起，图标区分（ν / E）。

### 1.8 两态跃迁读数与跃迁矩元表

- 选区读数：起点、终点（真实态或参考能级）→ 先 ν₁₂（这条跃迁本身的频率），再 Δν = ν₁₂ − ν(参考) 及其"相对"参考选择（频率读数控件，1.4）；"自动"为这两个态的零场 ν₁₂。下一行 |d| ＋ 若选中了激光，则加该激光在这条跃迁上的 Ω/2π。
- 起点和终点用同一种态记法（单一格式化函数）。
- 跃迁矩元表的频率列使用与 Δν 相同的参考和单位；"自动"时每行相对它自己两个态的零场频率。表头写出参考。只列 Ω ≠ 0 的分量。

## 2. 3D 视图（方向与偏振）

1. **跟随全局选择**：删除页内的激光标签。选中的对象（激光或磁场）粗线、带标签；其余对象细线淡化，标签仅在悬停时出现。点击 3D 中的箭头即选中该对象。
2. **视角**用"沿某方向看"表达，放在页标题行的分段控件里：`3D · 沿 x · 沿 y · 沿 z · 沿 B · 沿 k`。"沿 B"看量子化轴，"沿 k"沿选中光束看，此时偏振椭圆以真实形状显示，最利于判断偏振。现有的 XY/XZ/YZ 改为对应的"沿 z/沿 y/沿 x"。
3. **偏振画在原子处**：在垂直于 k 的平面上画偏振椭圆，带旋向箭头；同时在图例中给出相对 B 的 σ⁻/π/σ⁺ 分数（与检查器一致）。"▶ E" 改为有文字的"电场动画"开关。
4. **多个磁场**：每个磁场一条箭头，合成场（量子化轴）加粗；图例写出 |B| 和 ∠(k, B)。
5. 不做在 3D 中拖动箭头改方向（用户决定）；方向只在检查器中编辑。
6. 缩放、复位用 v3 的图标按钮（保留其 tooltip），"拖动旋转 · 滚轮缩放"提示只在首次使用时显示一次。
7. 颜色全部来自调色板 token，与能级图、列表中同一对象的身份色一致。

## 3. 初态

- 只在场景面板保留一处"初态"，删除 Population 页表单里的重复选择器。
- 初态是一个描述（物理模型已在数据层实现）：`单态 | 未极化 | 热分布 | 自定义`，用分段控件切换：
  - 单态：现有的态选择树；
  - 未极化：选择流形（全部基态 / F=1 / F=2）；
  - 热分布：温度 T（v3 Field，单位 K/mK/μK，"≈"规则；换单位保留数字，单位存在 `dynamics.temperatureUnit`），说明"在静态哈密顿量的基态本征态上按 Boltzmann 分布"；
  - 自定义：按 F、m_F 排成网格的权重输入（v3 SelectionGrid 风格），自动归一化，显示归一化后的分数。
- 场景只用 `dynamics.initialStateId`（和混合态的 `dynamics.initialState`）描述初态。

## 4. 在能级图中显示光移

物理上所有激光都进入主方程：每束开启且强度非零的光都是显式驱动，旋转项与反旋转项都保留，不分近共振与远失谐。每束光有一个开关 **"在能级图中显示光移"**（检查器"能级图"一节的"显示光移"）：它只决定未选中对象时能级图的背景是否含这束光的静态光移（全阶求解并给出数值误差界），不影响求解。

开关旁显示 |Ω/2Δ|；开关打开而这束光离共振太近时，写明静态光移不能代表它的作用（见 §6.8）。开关从不自动改变。

### 6.3 态记法（§1.8，已实现）

### 6.4 频率定义与读数（§1.2–1.4，已实现）

- **数据**：每个被定义的频率（激光、参考频率）只有一个 `frequency: FrequencyExpr`，即基准 + 偏移（MHz，规范存储），或者照写的真空波长（`types.ts`）。基准可以是绝对、零场跃迁、参考频率或另一束激光（偏频锁定）。操作者写数值所用的单位存在 `frequencyUnit`。激光所属 D 线 `line` 由频率派生。
- **格式**：频率只以表达式描述，没有其它写法（§6.17）。
- **解析**：`physics.ts` 的 `resolveSceneFrequencies` 按依赖顺序给每个对象算出派生的载频（中心频率 + 偏移）。基准不存在、成环或光频不是有限正数都拒绝，场景文件校验同样执行这一检查。
  - 派生载频带一个指纹（表达式，以及所跟随对象的载频）。指纹不变时，保存的载频按位保留，所以换基准、绝对频率与波长互换都不会重新舍入光频。
  - 导出再导入后光频逐位一致。
- **检查器"频率"一节**（激光与参考频率共用一套）：
  - **相对**：TreeCombo，可选绝对、零场跃迁、参考频率或激光。跟随某对象时，组合框写"跟随 探测光"；不提供它自己以及直接或间接跟随它的对象，所以选不出环。
  - **数值框**：标签依基准为"失谐 Δ / 偏频 Δ / 频率 ν / 波长 λ"，v3 Field，单位 Hz…THz；绝对时单位族多出 nm / μm。它是输入：换单位保留数字、基准不变，所以 Δ = +10 MHz 换成 GHz 即为 +10 GHz；绝对频率换成波长单位即把这些数字当作真空波长，反之亦然。没有按单位的范围，只有 ±5000 THz 和"光频为有限正数"；违反时按 §0.4 保留为无效的草稿。
  - 被别人跟随的对象，在本节末尾写"被 回泵光 跟随"。
- **删除被跟随的对象**：先确认；跟随它的对象改写到它自己链条末端的零场或绝对基准上，频率不变（`releaseFollowers`）。链接它的参考能级改成固定偏移，能量不变。
- **频率读数控件**（`frequency-controls.ts`）由三部分组成：v3 Readout（最多 12 位有效数字，小数两侧三位一组，被舍入时加"≈ "，tooltip 给出完整值）、单位选择器、"相对"基准选择器。没有基准可选的读数（两态读数的 ν₁₂）只有前两部分，读绝对频率。
  - 基准可选：绝对（读作光频，单位族多出 nm / μm）、零场跃迁、参考频率、激光。差值先减大的载频部分再减偏移。
  - 有"自动"的读数，"自动"是读数的使用者给出的一个有名字的参考频率（两态读数为"零场 ν₁₂"），组合框写"自动（零场 ν₁₂）"。
  - 单位和基准是该读数位置的显示偏好，存在场景的 `display.readouts` 中，随场景导出；它们不算对场景的编辑，也不进入物理请求或缓存键。偏好中的基准若此处已不提供，按默认处理。
- 检查器中，"频率 ν"一行是读数本身，下一行"读数相对"放基准和单位（检查器太窄，12 位读数与单位选择器放不进同一行）。

### 6.5 两态跃迁读数与跃迁矩元表（§1.8，已实现）

- 选区读数 ν₁₂ 是这条跃迁的光子频率 |E(终点) − E(起点)|/h；吸收还是受激辐射由起点、终点本身表明。所以起点、终点交换后读数不变，相对基准的读数总有意义。
- 读数一行分两段：先是 ν₁₂（绝对频率，单位可选，光学跃迁可读作波长，也可读作温度 ΔE/k_B，单位 mK：k_B/h = 20.836 619 GHz/K，取 SI 精确常数之比，即 1 mK ↔ 20.836 619 MHz），再是 Δν = ν₁₂ − ν(参考)、它的单位和"相对"参考；页面窄时两段之间换行。|d| 与选中激光的 Ω/2π 在下一行。原来的 ΔE/h 和 Δ_L 两项由这一行取代。
- "自动"参考是同一对态在零场（无磁场、无光移）下的 ν₁₂（`frequency-value.ts` 的 `zeroFieldStateValue`），所以默认的 Δν 是磁场和打开"显示光移"的激光让这条跃迁移动的量，与是否选中激光无关。它取代了原来"同一流形内读绝对频率，光学跃迁读选中激光或最近的零场跃迁"的规则。
  - 真实态的零场能量是它的零场超精细能级（`reference-energy.ts` 的 `zeroFieldLevel`，与参考能级"固定零场"锚点同一来源）。
  - 参考能级的零场对应是它自己的定义 E(锚点) ± hν(光子) + hδ，只把锚点换成零场能量：光子和 δ 是定义的一部分，不是移动。所以起点是它的锚点时 Δν = 0；锚点本就"固定零场"的参考能级，零场对应就是它自己。
  - 操作者仍可选激光（读出失谐）、参考频率、零场跃迁或绝对；这一选择和 Δν 的单位存在场景显示偏好 `display.readouts.pair` 中，ν₁₂ 的单位存在 `pair-frequency` 中。
- 跃迁矩元表只有一个频率列：每行是光子频率相对 Δν 的参考，单位相同，表头写出参考（如 `ν − ν(探测光) / MHz`）；"自动"时每行相对它自己两个态的零场频率，表头为 `ν − ν(零场) / MHz`。单位为波长时表格用 MHz（相对）或 THz（绝对）。只列 Ω ≠ 0 的分量。

### 6.6 能级图标注（§1.5，已实现）

- **未选中对象**：再点一次已选中的对象（场景列表、能级图中的光束箭头、3D 视图的箭头和图例）即取消选择，双击不算两次；能级图标题旁光束标签的 × 也取消选择。此时标题为"总场能级"，每张态卡片标注它相对零外场的总能移（磁场 + 打开"显示光移"的激光），检查器写明这一点。
- 能级图标题下一行写明当前标注的定义和背景，例如"标注：激发态 ν(参考态→e) − ν(探测光)，基态 (E − E参考)/h；正值表示更高；背景：B + 光镊"；参考态在激发态时写"激发态 (E − E参考)/h，基态为高出光子终点 E参考 − hν(探测光) 的量"。
- **符号（用户决定）**：选中激光时，每张态卡片读该态相对其锚点的高度 (E − E_锚点)/h，正值总表示该态更高（`transition-view.ts` 的 `levelReadoutMHz`）。锚点在参考态一侧是参考态本身，在光子一侧是光子终点 E_ref ± hν_L：
  - 参考态在基态（吸收）：基态 (E_g − E_ref)/h；激发态 ν(参考态→e) − ν_L。后者就是选区读数和跃迁矩元表"相对 该激光"的读数 ν − ν_L，图和读数一致。
  - 参考态在激发态（受激辐射）：同一激发流形内 (E_e − E_ref)/h；基态是它高出光子终点 E_ref − hν_L 的量，即 ν_L − ν(g←参考态)。此时读数给出的光子频率差 ν − ν_L 与卡片差一个符号，这是因为光子向下：光子频率越高，终点越低。
  - 另一激发流形的态（例如参考态在 D2 时的 D1 态）不标注。
  - 激光检查器的"失谐 Δ"仍是 ν_L − ν(基准)，即激光相对其基准的频率。
- 两个已知 bug 已修正：
  - 参考能级的标注按其能量所在流形的规则读，与真实态相同：在参考态一侧读 (E − E_ref)/h，在光子一侧读它高出光子终点的量（`transition-view.ts` 的 `referenceReadoutMHz`）。参考态本身是参考能级时，真实态的卡片也按这条规则读。
  - 光子方向（"受激辐射"）只属于参考能级：参考态切回真实态或"跟随动力学初态"时，过期的方向标记被清除（`setLaserReferenceState`）；对真实态，方向由该态是否在激发态决定（`laserEmits`）。

### 6.8 显示光移（§4，已实现）

- 检查器"能级图"一节只有一个开关"显示光移"，绑定激光的 `showLightShift`（新激光默认关，默认场景的光镊为开）。它只决定未选中对象时能级图背景是否含这束光的静态光移：打开的光的 Floquet 准能量，含 D 线旋转与反旋转项、32 态以外能级和 Rb⁺ 芯极化，全阶求解（`floquet-background.ts`），每个能级附数值误差界。它与动力学无关，也不进入请求或求解缓存键。

### 6.9 模型基与显示基

- 求解器返回的布居在模型基里，即静态 H0 的本征态（磁场 + 每束光经 32 态以外能级的二阶光移 + Rb⁺ 芯极化，`spectroscopy.ts` 的 `staticModelBackground`）；能级图用的是显示基（磁场 + 打开"显示光移"的激光的全阶静态光移）。
- 长期布居带有完整密度矩阵，按 v†ρv 精确投影到显示基。
- 指定时刻的 p(t) 只有布居。按态标签搬到显示基时，每个态的误差上界是 2δ + 2√δ，其中 δ = 1 − |⟨模型态|显示态⟩|²（`population-basis.ts`）。只有这个上界不超过 0.5%（布居精度）时，能级图才按 p(t) 着色，并标出"基差 ≤ x"；否则写明"p(t) 在模型基中，与能级图的基相差过大，未着色"。布居演化页的说明写明曲线在模型基中。

### 6.10 T 时刻的长期布居 p̄(T)

- p̄(T) 是时刻 t = T 的布居，只把该时刻附近的快振荡（激光间的拍频与光频微运动）平均掉，即 T 时刻态的零频 Fourier 分量（相位平均，或局部时间平均）。它不是 0 到 T 的时间平均。没有 t → ∞ 的长期布居（2026-10-28 取消）。两个求解器都按这个定义计算。界面上统一写"时刻 T""T 时刻的长期布居 p̄(T)""相位平均"，不写"观察时长"或"长期时间平均"。
- 时刻 T 可选 1 s · 100 ms，默认 1 s。它存在 `dynamics.meanHorizonUs`（1e5 / 1e6，必需；没有表示 t → ∞ 的 null）。T 不进入任何输入键：长期平均按 T 缓存（见 §6.18），有限时间轨迹与 T 无关。
- 控件原本应放在能级图基态处原来写"长期平均 / 长期布居"的位置，但那里与"5S₁/₂"标签同一行，900 px 时只剩约 95 px，放不下分段控件，所以放在工具栏的模式选择旁边。图上该处改为符号 p̄(T)。
- 模式选择为"长期布居 p̄ / 指定时刻 p(t)"。各处读数和标签写 p̄(1 s)、p̄(100 ms)。标签写的是结果实际所在的时刻 T，即求解器回传的 `horizonUs`。
- 请求选项为 `meanHorizonUs`。带长期平均的结果必须回传 `horizonUs`（算出与否都回传），且与请求一致；`scripts/native-protocol.mjs` 把它原样传给本机求解器。

### 6.11 求解器的新结果

- 计算详情显示最慢弛豫时间（自动选单位）：T 短于它时 p̄(T) 仍在弛豫。新的方法和状态句子，以及带数字的失败原因（预解求解停滞、工作量或模式上限、误差级数非有限等），都在 `solver-words.ts` 中译成中文；未知的句子原样显示。

### 6.12 参考（§1.6–1.7，已实现）

- 场景面板新增"参考"一节，用"＋"菜单添加参考频率或参考能级。列表中参考频率用身份色的 ν，参考能级用 E；两者都没有启用开关。
- **参考频率**：检查器只有"频率"一节（与激光相同的定义与读数）。选中它时，能级图按它标注失谐，没有耦合强度着色；两态读数的 Δν 可以选它作参考。它可以作为激光或其它参考频率的基准。身份色排在激光之后。
- **参考能级**：
  - 检查器"定义"一节有：锚点（态选择树）、锚点能量（随锚点 / 固定零场）、光子（无 / 某束激光 / 某个参考频率）、方向（吸收 +hν / 受激辐射 −hν）、偏移 δ（v3 Field），末尾写出 E = E(锚点) ± hν(来源) + hδ。
  - 链接光子后，参考能级随这束光或参考频率移动；取消链接或删除来源时，光子频率并入偏移，能量不变。§1.6 还允许直接写一个频率表达式作为光子，这里没有做，因为固定的光子频率用偏移 δ 就能表示。
  - 选中激光时新建的参考能级，锚点取这束光的参考态，并链接它的一个光子，取代原来的"取激光终点"。
  - 能级图详情中原来的"参考能级"编辑器已删除。

### 6.13 布居精度

- 布居精度固定为 0.5%（概率的绝对误差）：每个请求都发送 `populationTolerance: 0.005`（`types.ts` 的 `POPULATION_TOLERANCE`）。它不是用户设置，不在场景中，也不进入求解缓存键。求解器回传的 `requestedTolerance` 必须是 0.005。
- 场景中没有 `populationTolerance`；带它的文件按 §6.17 拒绝。
- 计算详情写"布居误差估计 ≤ x（目标 0.005）"。动力学页的设置为"时长、采样点数"和"显示曲线"两组。
- 轨迹最长 10 s，至多 2000 个采样点（2026-10-28；求解器核心解的就是这个范围，`types.ts` 的 `MAXIMUM_DURATION_US`、`MAXIMUM_SAMPLES`）。超出的输入不写入场景，输入框下写明原因（"时长不能超过 10 s""采样点数应为 2 至 2000"）。单位仍按 §0.4：输入框里的数字换单位时不变，所以 20 μs 换成 s 是 20 s，同样被拒绝，时长保持 20 μs，输入框标为无效直到下一次编辑。求解器也拒绝更长的时长或更多的采样点并写明原因；场景文件中超出的 `durationUs`、`samples` 导入时拒绝。

### 6.15 单位规则与按 NA 指定强度（2026-10-27）

- **单位规则**（§0.4，取代原来的"单位只改变读法"）：输入框换单位保留数字、物理量随之改变；计算出的读数换单位换算、物理量不变。逐项：
  - 输入：总时长、功率、束腰（功率与束腰方式）、局域强度（局域强度方式）、激光与参考频率的失谐/偏频/绝对频率/波长、参考能级的偏移 δ、热分布的温度 T。换单位写入框中的数字（去掉存储单位换算带来的浮点尾数，与 v3 spin box 的 ≈ 规则一致）乘以新单位，作为一次编辑：保存、重新求解。
  - 计算值：激光的"频率 ν"、两态读数 ν₁₂ 与 Δν、跃迁矩元表频率列、能级标注、钟跃迁、图上的时间与弛豫时间、功率方式和 NA 方式下的局域强度、NA 方式下的输出束腰。换单位只换算。
  - 违反物理约束的新单位（例如失谐 −500 MHz 换成 THz 使光频为负、偏移超出 ±1 000 000 THz）：框中保留新单位下的数字，标为无效并写明原因，场景不变，直到下一次编辑；Esc 放弃。
  - 单位随数值保存，都是必需的：`frequencyUnit`、`powerUnit`、`waistUnit`、`intensityUnit`、`dynamics.durationUnit`、热分布初态的 `dynamics.temperatureUnit`、参考能级的 `offsetUnit`。
  - 数值框不接受算式（v3 Field 只解析数字）；频率的"表达式"是基准加偏移，换单位时基准不变，只有偏移的单位改变。
- **按 NA 指定强度**：强度的"指定方式"有三种：局域强度、功率与束腰、功率与 NA。
  - 功率与 NA：输入为功率 P（单位规则同上）和数值孔径 NA（无量纲；原子在真空中，0 < NA ≤ 1，否则标为无效并写明原因）。光束充满物镜的 NA，输出束腰 w₀ = λ/(π·NA)，λ = c/ν 为这束光由其绝对频率得到的真空波长；这是傍轴高斯光束关系，NA 取 1/e² 远场半角的正弦，NA 大时只是近似。局域强度取高斯光束轴上的 I = 2P/(π·w₀²)，与功率与束腰方式相同。
  - 输出束腰和局域强度显示在禁用的数值框里，单位选择器可用（计算值，换单位换算）。激光频率改变时二者随之更新（强度锚点的指纹含功率、NA 与波长）。
  - 切换指定方式保持局域强度不变：目标方式的束腰或 NA 取这束光已有的值（没有时束腰 1.2 μm、NA 0.5），功率由强度反算。数据为 `intensityMode: 'na'` 与 `numericalAperture`；场景校验拒绝 0 < NA ≤ 1 以外的值和缺少 NA 的 NA 方式。

### 6.16 部分达到精度的结果与中间结果（2026-10-27）

- **不扣留算出的结果**（取代 §6.13 中"达不到即失败"的做法）。轨迹的 `populationAccuracy` 带 `sampleErrors`（每个采样时刻一个布居误差上界）、`estimatedMaximumError`（其最大值）和状态：全部 ≤ ε 为 `estimated-converged`，否则为 `estimated-partial`，并带 `reason`。长期布居（`meanHorizons` 的每一项）带 `estimatedError` 和 `withinTolerance`；`status` 仍是物理分类，`not-converged` 只表示没有算出可用结果。这些字段都是必需的：界面与求解器在同一个 EXE 中发布，不保留旧格式。
- **布居演化图**：所有曲线照画；误差超过 0.5% 的采样（到相邻采样的一半为止）铺浅橙色背景，曲线在那里画成淡色虚线，图例加一项"估计误差 > 0.5%"。悬停读数在时刻后写该时刻的 ±误差，超出时为橙色并注明。读数放在光标线较宽的一侧，图窄时按那一侧的宽度换行，不盖住光标，指针始终在图上；新的检查点或最终结果替换图时，打开的读数留在原采样上（同一次计算的检查点与最终结果采样相同）。
- **状态栏**：部分达到时加一句，例如"t ≤ 0.021 μs 估计误差最大 0.61%（超过 0.5%），其余时刻 ≤ 0.5%"（`accuracy.ts`）；p̄(T) 超出时写"p̄(1 s) 估计误差 0.72%（超过 0.5%）"。两者同时出现时状态栏写短句"t ≤ 0.021 μs 误差最大 0.61% · p̄(1 s) 误差 0.72%（均超 0.5%）"，完整的两句在它的悬停提示中，800 px 宽时也放得下一行。
- **每个输出按自己的误差界判断**（2026-10-28）：`estimated-converged` 表示轨迹每个采样点的误差上界都在 0.5% 内，长期平均的 `withinTolerance: true` 表示它自己的误差上界（含投影到密度矩阵的改变量）在 0.5% 内；否则分别为 `estimated-partial` 与 false，文字写"超过 0.5%"。求解器不再有"上界在 0.5% 内但未确认收敛"的结果（原来的"未确认收敛"已取消）：读取时状态与误差界不一致的结果被拒绝。
- **能级图**："指定时刻"的误差超过 0.5%，或 p̄(T) 超出时，仍按算出的布居着色；工具栏时刻旁出现橙色"⚠ 估计误差 x%"，能级的悬停文字在数值后写"（估计误差 x%，超过 0.5%）"。
- **中间结果**：请求带 `stream: true` 时，求解器每到一个检查点发一个 `checkpoint` 事件，内容与最终结果相同，另加 `progress: true`（只求长期布居时是单行 t = 0）；最后的 `result` 是最好的检查点，不带 `progress`。原来的 `asymptotic`（稳态进度）事件已取消。检查点不画出来（2026-10-28）：计算期间图、能级和读数都不变，状态栏只写"布居计算中… · 当前估计误差最大 x%"；最终结果到来时一次画出全部内容，不会出现先显示、后消失的误差标记。界面在后台保留最后收到的检查点：按"停止"后它成为结果，一次画出，按部分达到精度的结果标出各时刻的误差，状态栏写"计算已停止 · 显示最后的中间结果：t ≤ 0.42 μs 误差最大 1%（超过 0.5%）"（短句；几段时刻时只写段数，如"2 段时刻误差最大 1%"，位置看图中的浅橙色背景；完整的句子在悬停提示中）；求解失败时同样保留它，状态栏写"计算失败 · 显示最后的中间结果：…"。没有收到检查点就停止时，什么也不画，状态栏写"计算已停止 · 修改参数后重新计算"。
- **详情**：计算详情的"布居误差估计"写最大误差和是否部分超出，其下一行写超出的时刻和求解器给出的原因；有长期布居误差时加"长期布居误差估计"一行。模型说明写明每个时刻的误差和部分达到时的显示方式。

### 6.17 唯一的场景格式（2026-10-28）

- 场景只有一种格式：`types.ts` 的 `Scene`，`version: 2`（`SCENE_VERSION`）。`scene-file.ts` 严格按它校验：必需字段齐全且在范围内，没有任何其它字段。早先版本写的文件不再读入、也不迁移：导入时拒绝并写明原因（如"场景文件不符合当前格式（version 2）：version 为 1，应为 2"或"lasers[0] 缺少 showLightShift"）。
- 场景只由操作者载入（导入、示例）。界面不自动保存场景，启动时总是默认场景（`scene-file.ts` 的 `startupScene`），早先版本存在本机浏览器存储里的场景、编辑基准和能级标签在启动时删除；本机只保留求解失败的诊断记录，它不是场景数据。能级标签 1、2 只在本次运行中有效。"替换当前场景"的确认只比较本次载入或导出之后的修改。
- 必需：`name`、`fields`、`lasers`、`referenceFrequencies`、`references`、`marks`、`dynamics`；磁场的 `direction`；激光的 `frequency`、`frequencyUnit`、`line`（派生，读入后按频率重算）、`showLightShift`、`intensityMode`、`intensityMWcm2`、`powerUnit`、`waistUnit`、`intensityUnit`、`direction`、`polarizationAngleDeg`、`ellipticityDeg`、`phaseDeg`，以及所选强度方式的输入（功率与束腰：`powerMW`、`waistUm`；功率与 NA：`powerMW`、`numericalAperture`）；参考频率的 `frequency`、`frequencyUnit`；参考能级的 `anchorId`、`anchorMode`、`offsetMHz`、`offsetUnit`；`dynamics` 的 `initialStateId`、`monitoredStateIds`、`monitorMode`、`monitoredGroupIds`、`durationUs`、`durationUnit`、`samples`、`meanHorizonUs`。
- 可选（本身就是可有可无的）：`display`（读数偏好）；激光的 `referenceStateId`、`referenceProcess`，以及别的强度方式留下的 `powerMW`、`waistUm`、`numericalAperture`；参考能级的 `photon`；混合初态的 `dynamics.initialState`，热分布时还有 `dynamics.temperatureUnit`（且只在热分布时有）；派生的 `frequencyAnchor`、`intensityAnchor`（没有时由输入算出，有时只在指纹相符时使用）。
- 取消的旧写法：`initialF/initialM`、`dynamics.laserId`、`dynamics.quality`、`dynamics.populationTolerance`、激光的 `regime`、`detuningMHz/referenceTransition/frequencyMode/wavelengthNm/detuningUnit`、以角度 `thetaDeg/phiDeg` 和 `directionAnchor` 写的方向、预设与跟随标记，以及缺省 `meanHorizonUs`、单位、`showLightShift`、`phaseDeg`、`intensityMode` 时的补齐。

### 6.18 两个时刻 T 一次算出，切换 T 即时显示（2026-10-28）

- **求解器契约**：每次长期平均的计算都给出两个标准时刻 100 ms 和 1 s 的结果（没有 t → ∞），长期平均只有这一种写法：`meanHorizons`，两项，每项 `{horizonUs: 1e5 | 1e6, populations, densityReal, densityImag, estimatedError, withinTolerance, status, reason}`，算出的项 `status` 为 `time-average`（T 时刻的相位平均）。请求的 `meanHorizonUs` 只能是这两个时刻之一（其它值和 null 都报错）；它指明界面当作长期平均读的那一项，诊断里长期密度的数值验证属于这一项。稳态、稳态残差、守恒量个数和"依赖初态"的分类都已取消。原来与这一项重复的顶层字段（`asymptoticPopulations`、`asymptoticStatus`、`horizonUs` 等）已取消。完整请求带 `includeMean: false` 时只返回轨迹（没有 `meanHorizons`）。
- **严格读取**（`solver-client.ts`）：请求了长期平均（算出与否）就必须有 `meanHorizons`，没有请求就不能有。列表恰好两项，两个 T 各一项（顺序不限）；每项按同一规则读：状态是 `time-average` 或 `not-converged`；算出的项有 32 个概率、复密度（对角与布居一致、厄米、正性子式）、误差上界，且 `withinTolerance` 与"误差 ≤ 0.5%"一致；未算出的项没有布居和密度。请求的 T 那一项就是结果的长期平均（`mean`）。方法和最慢弛豫时间属于这次计算，两个 T 共用；长期密度的数值验证只属于请求的 T。界面与求解器同版发布，没有兼容旧求解器的路径。
- **缓存**（`current-results.ts`、`solve-plan.ts`、`dynamics-cache-key.ts`）：长期平均按"长期平均的输入 + T"缓存，输入是物理参数与初态（`meanInputsKey`），不含时长、采样点数和 T；轨迹按"轨迹的输入"（`trajectoryInputsKey`：长期平均的输入 + 时长 + 采样点数）缓存。每个结果带来的两个 T 都存入。只保留当前输入的结果：物理参数或初态一变，两个 T 一起作废；时长或采样点数一变，只作废轨迹。回到早先的输入要重新计算。
- **请求**：页面需要什么就只请求什么。长期布居模式（能级图 p̄）只需要 T 时刻的长期平均，其余页面还需要轨迹。缓存里有 T 时刻的长期平均时，切换 T 立即显示，不发请求；改时长或采样点数（以及其它不改变长期平均输入的修改）只请求轨迹（`includeMean: false`），长期平均用缓存中的。都没有时发完整请求；只缺长期平均时发只求长期平均的请求。正在进行的请求若能带来所缺的内容（长期平均的计算带来两个 T），换页面或换 T 不会取消或重发它。
- 其余不变：计算期间不画中间结果，最终结果一次画出；"停止"后最后一个检查点成为结果（它的轨迹，以及在没有最终结果的 T 上它的长期平均，都标为中间结果）；每个时刻的误差标记照旧。

### 6.19 模型范围：警告，不是拒绝（2026-10-28）

- 没有波长窗口：任何波长的激光都可以设置和计算。模型在哪里不代表激光的作用，就在哪里写明，结果照常计算和显示（`spectroscopy.ts` 的 `modelScope`）。
- 两种情形。其一，激光接近 32 态以外能级（6P、nS、nD）的共振：这些能级只作为二阶静态（van Vleck）光移进入 H0，耦合/失谐比 |Ω/2Δ| 超过 1%（`STATIC_MIXING_LIMIT`）或虚跃迁失谐不足 10 GHz（`OUTSIDE_GAP_MHZ`）时，二阶项不再代表它们。这与能级图画静态光移的规则是同一条：打开"显示光移"的这束光在能级图中也不画光移（"离共振太近"）；能级图另有 D 线自己的条件（失谐 ≥ 100 MHz），动力学中 D 线是显式驱动，不需要它。原来动力学在这里拒绝构建模型，现在只在恰好共振、二阶项无定义时拒绝。其二，激光波长短于 5P 的光电离阈值（5P₃/₂ 479.1 nm、5P₁/₂ 473.7 nm，由 Rb 电离能 33 690.8048 cm⁻¹ 减去 5P 能量得到）：光电离不在模型内。
- 显示：状态栏下方一行橙色文字，每页都在："超出模型范围（结果照常给出）："后接每条说明，点名激光与原因，例如"「蓝光」的波长 450 nm 短于 5P₃/₂ 和 5P₁/₂ 的光电离阈值（479.1 nm、473.7 nm）：光电离不在模型内。"或"「telecom」离 4D5/2 的虚跃迁失谐只有 4.69 GHz（不足 10 GHz）：32 态以外的能级（6P、nS、nD）只作为二阶静态光移进入模型，这里超出它的适用范围。"同一频率的几束光作为一个载频一起判断、一起点名。详情页"当前计算"中重复这些说明；没有这些情形时这一行不出现。
