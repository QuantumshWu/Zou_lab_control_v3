# Atom Workbench：频率体系、3D 视图与初态的统一交互设计

本文是界面第二阶段的实现依据。第一阶段（v3 外框、状态条、标签页、Field、用语与格式、tooltip、窄窗口）完成后，在其基础上实现本文内容。

## 0. 总原则

1. **一个选择，处处一致。** 全局只有一个"当前对象"（磁场、激光、参考频率、参考能级之一，或无）。场景面板列表、能级图中的箭头、3D 视图中的箭头都可以选中对象，再点一次已选中的对象即取消选择（回到"无"）；检查器编辑当前对象；三个视图都高亮当前对象。不再有视图内的第二套选择（例如 3D 页的激光标签）。
2. **对象有统一身份色。** 每束激光、每个参考频率有一个颜色，出现在列表图标、能级图中它的跃迁、3D 视图中它的箭头和偏振椭圆上。磁场固定为绿色。颜色来自 token 调色板，不写死。
3. **定义与读数分开。** "这个量是怎么定义的"（会影响物理或会让对象跟随别的对象变化）和"这个量以什么基准、什么单位显示"（纯显示）是两件事，界面上用不同控件、不同位置表达。
4. **单位遵循 v3 规则（与 Device Control 相同）。** 显示出来的（计算得到的）数值换单位时换算：物理量不变，数字随单位改变；操作者在输入框里写下的数值换单位时保留数字：单位真的改变，物理量随之改变（总时长 10 μs 换成 ms 即为 10 ms）。所以输入框换单位是一次真实的参数修改，自动计算像对待任何编辑一样重新求解。新的物理量违反物理约束时（例如光频不再为正），不夹取、不悄悄换算：框中保留新单位下的这些数字并标为无效、写明原因，场景保持原值，直到下一次编辑；Esc 放弃它。同一个量的角色随模式而定：功率与束腰方式下局域强度是计算值（换算），局域强度方式下它是输入（保留数字）。场景保存数值时连同它的单位。显示时不精确的数值写"≈ 四位有效数字"，编辑时保留完整数值；步长按 v3 的 firstStep 规则取最后一位有效数字；换单位后步长重置；不再有"每个单位 ±5000"的伪范围，只保留物理约束（光频 > 0）。

## 1. 频率体系

### 1.1 三类"频率对象"与内置基准

| 类别 | 例 | 来源 |
|---|---|---|
| 内置基准：绝对零点 | ν = 0（即绝对光频） | 固定 |
| 内置基准：零场跃迁 | D2 F=2→F′=3、D1 F=1→F″=2、5P₁/₂ F″→5P₃/₂ F′ | 固定列表（现有 `zeroFieldTransitionOptions`） |
| 激光 | 探测光、repump、光镊 | 场景对象 |
| 参考频率（新） | "冷却光锁频点"、"Rydberg 双光子中心" | 场景对象 |

参考频率是没有强度、偏振、方向的"虚拟激光"，只携带一个频率。它在界面上的行为与激光的频率部分完全一致：可以被选中（能级图显示到它的失谐，但没有耦合强度着色）、可以作为别的频率的基准。

### 1.2 频率表达式（唯一的数据形式）

每个被"定义"的频率（激光频率、参考频率）都是一个表达式：

```ts
type FrequencyBase =
  | {kind:'absolute'}                                   // ν = offset
  | {kind:'transition'} & ZeroFieldTransition           // ν = ν⁰(F→F′) + offset
  | {kind:'reference', id:string}                       // ν = ν(参考频率 id) + offset
  | {kind:'laser', id:string};                          // ν = ν(激光 id) + offset（偏频锁定）
type FrequencyExpr =
  | {base:FrequencyBase; offsetMHz:number}              // 主要形式；offsetMHz 为规范存储
  | {wavelengthNm:number};                              // 只用于"按真空波长定义"的绝对频率
```

- 绝对光频用 `accurateSum` 组合（与现有 `captureLaserFrequencyAnchor` 同样的精度保护），不在 THz 量级上丢失 Hz 级偏移。
- `wavelengthNm` 是"操作者写下的就是波长"，波长输入不被换算成频率存储，避免 852 nm 被写回成 351.86… THz 的十几位小数。
- 频率只以 `frequency: FrequencyExpr` 加它的单位描述（单一真相源）。激光所属 D 线（`line`）不是输入，而是由频率派生的显示属性。

### 1.3 定义行为："锁定"语义

- 激光和参考频率的检查器里，"频率"一行由三部分组成：**数值框**（v3 Field，带单位选择器）+ **"相对"基准选择器**（TreeCombo）。数值框里是相对基准的偏移；基准为"绝对"时数值框里是绝对频率，单位族多出"波长"（nm、μm）。
- **切换基准不改变物理频率**：切换的瞬间按新基准重新计算偏移（与现有 `setLaserTransitionReference` 的语义一致）。
- **之后基准变化时，依赖它的对象跟着变**：例如 repump 定义为"相对 探测光 +6.568 GHz"，探测光改频后 repump 随之移动。这对应实验里的偏频锁定，是有意的语义。依赖关系在检查器中可见（基准行写明"跟随 探测光"），被别人依赖的对象在检查器底部列出"被 repump 跟随"。
- **防环**：基准选择器中不列出直接或间接依赖当前对象的对象；场景文件校验也拒绝环。
- 删除一个被依赖的对象前确认，并把依赖者转换为等效的绝对/零场定义（物理频率不变）。

### 1.4 读数行为："相对…显示"

所有派生出来的频率读数（激光的绝对频率 ν、两态跃迁频率、跃迁矩元表的频率列、能级图标注之外的频率）统一用一个**频率读数控件**：

```
ν₁₂   +6.834 682 610 9 GHz   [GHz ▾]   相对 [绝对 ▾]
```

- 读数用 v3 `Readout`，不可编辑；"≈"规则同上。
- 读数是显示：它的单位选择器和"相对"基准选择器只换算读法，记为该读数位置的显示偏好，存入场景（与其它显示偏好一起），不进入物理请求，也不进入求解缓存键。
- 两态跃迁读数先给出跃迁频率 ν₁₂ 本身，再给出 Δν = ν₁₂ − ν(参考) 和它的"相对"参考（§1.8）。参考的默认值"自动"是这两个态在零场（无磁场、无光移）下的 ν₁₂，所以默认的 Δν 就是磁场和打开"显示光移"的激光让这条跃迁移动的量；也可以选激光、参考频率、零场跃迁或绝对。

### 1.5 能级图标注（保持现有语义）

- **未选中任何对象**：能级位置与标注显示磁场 + 打开"显示光移"的激光带来的移动（总能移）。再点一次已选中的对象（或能级图标题旁光束标签的 ×）即回到这里。
- **选中激光**：该激光的各跃迁按耦合强度着色；每个态标注"该态的跃迁频率 − 激光频率"，正值表示该态更高：激发态 Δ = ν(参考态→e) − ν_L；基态标注相对参考基态的频率 (E_g − E_ref)/h（F=1 在 F=2 参考态之下读 −6.83 GHz）。激光检查器自己的"失谐 Δ"仍是 ν_L − ν(基准)，即激光相对其基准的频率，方向相同。
- **选中参考频率**：同上，但没有耦合强度着色（只有频率，没有强度和偏振）。
- 修正已知的两个 bug：参考能级位于基态范围时参考列的同侧规则；参考态切回真实态时清除过期的"受激辐射"方向标记。
- 图例一行写明当前标注的定义："激发态 ν(参考态→e) − ν(探测光)，基态 (E − E参考)/h；正值表示更高；背景：B + 光镊"。

### 1.6 参考能级（保留，并与频率体系统一）

参考能级是图示用的虚拟能级（不进入动力学）。定义改为：

```ts
interface ReferenceLevel { id; name; anchorId:string; anchorMode:'follow'|'zero-field';
  photon?: {frequency: FrequencyExpr | {object:'laser'|'reference', id:string}; direction:'absorb'|'emit'};
  offsetMHz:number }   // E = E(锚点) ± hν(photon) + h·offset
```

现有的"取激光终点"（一次性把 ±hν_L 抄进 offset）改为可选择**链接**一束激光或参考频率：例如"虚拟中间态 = |2,0⟩ + 一个探测光光子"，探测光改频时它跟着移动。也可以不链接，只写固定偏移。

### 1.7 场景面板结构

```
实验场景
  磁场        [＋]
  激光        [＋]
  参考        [＋▾]  （菜单：参考频率 / 参考能级）
     ν  冷却锁频点     D2 F=2→F′=3 −12 MHz
     E  虚拟中间态     |2,0⟩ + 探测光
  初态
```

参考频率与参考能级同属"图示参考"，不参与物理，列在一起，图标区分（ν / E）。

### 1.8 两态跃迁读数与跃迁矩元表

- 选区读数：起点、终点（真实态或参考能级）→ 先 ν₁₂（这条跃迁本身的频率），再 Δν = ν₁₂ − ν(参考) 及其"相对"参考选择（频率读数控件，1.4）；"自动"为这两个态的零场 ν₁₂。下一行 |d| ＋ 若选中了激光，则加该激光在这条跃迁上的 Ω/2π。
- 起点和终点用同一种态记法（单一格式化函数）。
- 跃迁矩元表的频率列使用与 Δν 相同的参考和单位；"自动"时每行相对它自己两个态的零场频率。表头写出参考。只列 Ω ≠ 0 的分量。

## 2. 3D 视图（方向与偏振）

1. **跟随全局选择**：删除页内的激光标签。选中的对象（激光或磁场）粗线、带标签；其余对象细线淡化，标签仅在悬停时出现。点击 3D 中的箭头即选中该对象。
2. **视角**用"沿某方向看"表达，放在页标题行的分段控件里：`3D · 沿 x · 沿 y · 沿 z · 沿 B · 沿 k`。"沿 B"看量子化轴，"沿 k"沿选中光束看，此时偏振椭圆以真实形状显示，最利于判断偏振。现有的 XY/XZ/YZ 改为对应的"沿 z/沿 y/沿 x"。
3. **偏振画在原子处**：在垂直于 k 的平面上画偏振椭圆，带旋向箭头；同时在图例中给出相对 B 的 σ⁻/π/σ⁺ 分数（与检查器一致）。"▶ E" 改为有文字的"电场动画"开关。
4. **多个磁场**：每个磁场一条箭头，合成场（量子化轴）加粗；图例写出 |B| 和 ∠(k, B)。
5. 不做在 3D 中拖动箭头改方向（用户决定）；方向只在检查器中编辑。
6. 缩放、复位用 v3 的图标按钮（保留其 tooltip），"拖动旋转 · 滚轮缩放"提示只在首次使用时显示一次。
7. 颜色全部来自调色板 token，与能级图、列表中同一对象的身份色一致。

## 3. 初态

- 只在场景面板保留一处"初态"，删除 Population 页表单里的重复选择器。
- 初态是一个描述（物理模型已在数据层实现）：`单态 | 未极化 | 热分布 | 自定义`，用分段控件切换：
  - 单态：现有的态选择树；
  - 未极化：选择流形（全部基态 / F=1 / F=2）；
  - 热分布：温度 T（v3 Field，单位 K/mK/μK，"≈"规则；换单位保留数字，单位存在 `dynamics.temperatureUnit`），说明"在静态哈密顿量的基态本征态上按 Boltzmann 分布"；
  - 自定义：按 F、m_F 排成网格的权重输入（v3 SelectionGrid 风格），自动归一化，显示归一化后的分数。
- 场景只用 `dynamics.initialStateId`（和混合态的 `dynamics.initialState`）描述初态。

## 4. 在能级图中显示光移

物理上所有激光都进入主方程：每束开启且强度非零的光都是显式驱动，旋转项与反旋转项都保留，不分近共振与远失谐。每束光有一个开关 **"在能级图中显示光移"**（检查器"能级图"一节的"显示光移"）：它只决定未选中对象时能级图的背景是否含这束光的静态光移（全阶求解并给出数值误差界），不影响求解。

开关旁显示 |Ω/2Δ|；开关打开而这束光离共振太近时，写明静态光移不能代表它的作用（见 §6.8）。开关从不自动改变。

### 6.4 频率定义与读数（§1.2–1.4，已实现）

- **数据**：每个被定义的频率（激光、参考频率）只有一个 `frequency: FrequencyExpr`，即基准 + 偏移（MHz，规范存储），或者照写的真空波长（`types.ts`）。基准可以是绝对、零场跃迁、参考频率或另一束激光（偏频锁定）。操作者写数值所用的单位存在 `frequencyUnit`。激光所属 D 线 `line` 由频率派生。
- **格式**：频率只以表达式描述，没有其它写法（§6.17）。
- **解析**：`physics.ts` 的 `resolveSceneFrequencies` 按依赖顺序给每个对象算出派生的载频（中心频率 + 偏移）。基准不存在、成环或光频不是有限正数都拒绝，场景文件校验同样执行这一检查。
  - 派生载频带一个指纹（表达式，以及所跟随对象的载频）。指纹不变时，保存的载频按位保留，所以换基准、绝对频率与波长互换都不会重新舍入光频。
  - 导出再导入后光频逐位一致。
- **检查器"频率"一节**（激光与参考频率共用一套）：
  - **相对**：TreeCombo，可选绝对、零场跃迁、参考频率或激光。跟随某对象时，组合框写"跟随 探测光"；不提供它自己以及直接或间接跟随它的对象，所以选不出环。
  - **数值框**：标签依基准为"失谐 Δ / 偏频 Δ / 频率 ν / 波长 λ"，v3 Field，单位 Hz…THz；绝对时单位族多出 nm / μm。它是输入：换单位保留数字、基准不变，所以 Δ = +10 MHz 换成 GHz 即为 +10 GHz；绝对频率换成波长单位即把这些数字当作真空波长，反之亦然。没有按单位的范围，只有 ±5000 THz 和"光频为有限正数"；违反时按 §0.4 保留为无效的草稿。
  - 被别人跟随的对象，在本节末尾写"被 回泵光 跟随"。
- **删除被跟随的对象**：先确认；跟随它的对象改写到它自己链条末端的零场或绝对基准上，频率不变（`releaseFollowers`）。链接它的参考能级改成固定偏移，能量不变。
- **频率读数控件**（`frequency-controls.ts`）由三部分组成：v3 Readout（最多 12 位有效数字，小数两侧三位一组，被舍入时加"≈ "，tooltip 给出完整值）、单位选择器、"相对"基准选择器。没有基准可选的读数（两态读数的 ν₁₂）只有前两部分，读绝对频率。
  - 基准可选：绝对（读作光频，单位族多出 nm / μm）、零场跃迁、参考频率、激光。差值先减大的载频部分再减偏移。
  - 有"自动"的读数，"自动"是读数的使用者给出的一个有名字的参考频率（两态读数为"零场 ν₁₂"），组合框写"自动（零场 ν₁₂）"。
  - 单位和基准是该读数位置的显示偏好，存在场景的 `display.readouts` 中，随场景导出；它们不算对场景的编辑，也不进入物理请求或缓存键。偏好中的基准若此处已不提供，按默认处理。
- 检查器中，"频率 ν"一行是读数本身，下一行"读数相对"放基准和单位（检查器太窄，12 位读数与单位选择器放不进同一行）。

### 6.5 两态跃迁读数与跃迁矩元表（§1.8，已实现）

- 选区读数 ν₁₂ 是这条跃迁的光子频率 |E(终点) − E(起点)|/h；吸收还是受激辐射由起点、终点本身表明。所以起点、终点交换后读数不变，相对基准的读数总有意义。
- 读数一行分两段：先是 ν₁₂（绝对频率，单位可选，光学跃迁可读作波长，也可读作温度 ΔE/k_B，单位 mK：k_B/h = 20.836 619 GHz/K，取 SI 精确常数之比，即 1 mK ↔ 20.836 619 MHz），再是 Δν = ν₁₂ − ν(参考)、它的单位和"相对"参考；页面窄时两段之间换行。|d| 与选中激光的 Ω/2π 在下一行。原来的 ΔE/h 和 Δ_L 两项由这一行取代。
- "自动"参考是同一对态在零场（无磁场、无光移）下的 ν₁₂（`frequency-value.ts` 的 `zeroFieldStateValue`），所以默认的 Δν 是磁场和打开"显示光移"的激光让这条跃迁移动的量，与是否选中激光无关。它取代了原来"同一流形内读绝对频率，光学跃迁读选中激光或最近的零场跃迁"的规则。
  - 真实态的零场能量是它的零场超精细能级（`reference-energy.ts` 的 `zeroFieldLevel`，与参考能级"固定零场"锚点同一来源）。
  - 参考能级的零场对应是它自己的定义 E(锚点) ± hν(光子) + hδ，只把锚点换成零场能量：光子和 δ 是定义的一部分，不是移动。所以起点是它的锚点时 Δν = 0；锚点本就"固定零场"的参考能级，零场对应就是它自己。
  - 操作者仍可选激光（读出失谐）、参考频率、零场跃迁或绝对；这一选择和 Δν 的单位存在场景显示偏好 `display.readouts.pair` 中，ν₁₂ 的单位存在 `pair-frequency` 中。
- 跃迁矩元表只有一个频率列：每行是光子频率相对 Δν 的参考，单位相同，表头写出参考（如 `ν − ν(探测光) / MHz`）；"自动"时每行相对它自己两个态的零场频率，表头为 `ν − ν(零场) / MHz`。单位为波长时表格用 MHz（相对）或 THz（绝对）。只列 Ω ≠ 0 的分量。

### 6.6 能级图标注（§1.5，已实现）

- **未选中对象**：再点一次已选中的对象（场景列表、能级图中的光束箭头、3D 视图的箭头和图例）即取消选择，双击不算两次；能级图标题旁光束标签的 × 也取消选择。此时标题为"总场能级"，每张态卡片标注它相对零外场的总能移（磁场 + 打开"显示光移"的激光），检查器写明这一点。
- 能级图标题下一行写明当前标注的定义和背景，例如"标注：激发态 ν(参考态→e) − ν(探测光)，基态 (E − E参考)/h；正值表示更高；背景：B + 光镊"；参考态在激发态时写"激发态 (E − E参考)/h，基态为高出光子终点 E参考 − hν(探测光) 的量"。
- **符号（用户决定）**：选中激光时，每张态卡片读该态相对其锚点的高度 (E − E_锚点)/h，正值总表示该态更高（`transition-view.ts` 的 `levelReadoutMHz`）。锚点在参考态一侧是参考态本身，在光子一侧是光子终点 E_ref ± hν_L：
  - 参考态在基态（吸收）：基态 (E_g − E_ref)/h；激发态 ν(参考态→e) − ν_L。后者就是选区读数和跃迁矩元表"相对 该激光"的读数 ν − ν_L，图和读数一致。
  - 参考态在激发态（受激辐射）：同一激发流形内 (E_e − E_ref)/h；基态是它高出光子终点 E_ref − hν_L 的量，即 ν_L − ν(g←参考态)。此时读数给出的光子频率差 ν − ν_L 与卡片差一个符号，这是因为光子向下：光子频率越高，终点越低。
  - 另一激发流形的态（例如参考态在 D2 时的 D1 态）不标注。
  - 激光检查器的"失谐 Δ"仍是 ν_L − ν(基准)，即激光相对其基准的频率。
- 两个已知 bug 已修正：
  - 参考能级的标注按其能量所在流形的规则读，与真实态相同：在参考态一侧读 (E − E_ref)/h，在光子一侧读它高出光子终点的量（`transition-view.ts` 的 `referenceReadoutMHz`）。参考态本身是参考能级时，真实态的卡片也按这条规则读。
  - 光子方向（"受激辐射"）只属于参考能级：参考态切回真实态或"跟随动力学初态"时，过期的方向标记被清除（`setLaserReferenceState`）；对真实态，方向由该态是否在激发态决定（`laserEmits`）。

### 6.8 显示光移（§4，已实现）

### 6.9 模型基与显示基

### 6.10 T 时刻的长期布居 p̄(T)

- p̄(T) 是时刻 t = T 的布居，只把该时刻附近的快振荡（激光间的拍频与光频微运动）平均掉，即 T 时刻态的零频 Fourier 分量（相位平均，或局部时间平均）。它不是 0 到 T 的时间平均。没有 t → ∞ 的长期布居（2026-10-28 取消）。两个求解器都按这个定义计算。界面上统一写"时刻 T""T 时刻的长期布居 p̄(T)""相位平均"，不写"观察时长"或"长期时间平均"。
- 时刻 T 可选 1 s · 100 ms，默认 1 s。它存在 `dynamics.meanHorizonUs`（1e5 / 1e6，必需；没有表示 t → ∞ 的 null）。T 不进入任何输入键：长期平均按 T 缓存（见 §6.18），有限时间轨迹与 T 无关。
- 控件原本应放在能级图基态处原来写"长期平均 / 长期布居"的位置，但那里与"5S₁/₂"标签同一行，900 px 时只剩约 95 px，放不下分段控件，所以放在工具栏的模式选择旁边。图上该处改为符号 p̄(T)。
- 模式选择为"长期布居 p̄ / 指定时刻 p(t)"。各处读数和标签写 p̄(1 s)、p̄(100 ms)。标签写的是结果实际所在的时刻 T，即求解器回传的 `horizonUs`。
- 请求选项为 `meanHorizonUs`。带长期平均的结果必须回传 `horizonUs`（算出与否都回传），且与请求一致；`scripts/native-protocol.mjs` 把它原样传给本机求解器。

### 6.11 求解器的新结果

- 计算详情显示最慢弛豫时间（自动选单位）：T 短于它时 p̄(T) 仍在弛豫。新的方法和状态句子，以及带数字的失败原因（预解求解停滞、工作量或模式上限、误差级数非有限等），都在 `solver-words.ts` 中译成中文；未知的句子原样显示。

### 6.13 布居精度

- 布居精度固定为 1%（概率的绝对误差）：每个请求都发送 `populationTolerance: 0.01`（`types.ts` 的 `POPULATION_TOLERANCE`）。它不是用户设置，不在场景中，也不进入求解缓存键。求解器回传的 `requestedTolerance` 必须是 0.01。
- 场景中没有 `populationTolerance`；带它的文件按 §6.17 拒绝。
- 计算详情写"布居误差估计 ≤ x（目标 0.01）"。动力学页的设置为"时长、采样点数"和"显示曲线"两组。
- 轨迹最长 10 s，至多 2000 个采样点（2026-10-28；求解器核心解的就是这个范围，`types.ts` 的 `MAXIMUM_DURATION_US`、`MAXIMUM_SAMPLES`）。超出的输入不写入场景，输入框下写明原因（"时长不能超过 10 s""采样点数应为 2 至 2000"）。单位仍按 §0.4：输入框里的数字换单位时不变，所以 20 μs 换成 s 是 20 s，同样被拒绝，时长保持 20 μs，输入框标为无效直到下一次编辑。求解器也拒绝更长的时长或更多的采样点并写明原因；场景文件中超出的 `durationUs`、`samples` 导入时拒绝。

### 6.15 单位规则与按 NA 指定强度（2026-10-27）

- **单位规则**（§0.4，取代原来的"单位只改变读法"）：输入框换单位保留数字、物理量随之改变；计算出的读数换单位换算、物理量不变。逐项：
  - 输入：总时长、功率、束腰（功率与束腰方式）、局域强度（局域强度方式）、激光与参考频率的失谐/偏频/绝对频率/波长、参考能级的偏移 δ、热分布的温度 T。换单位写入框中的数字（去掉存储单位换算带来的浮点尾数，与 v3 spin box 的 ≈ 规则一致）乘以新单位，作为一次编辑：保存、重新求解。
  - 计算值：激光的"频率 ν"、两态读数 ν₁₂ 与 Δν、跃迁矩元表频率列、能级标注、钟跃迁、图上的时间与弛豫时间、功率方式和 NA 方式下的局域强度、NA 方式下的输出束腰。换单位只换算。
  - 违反物理约束的新单位（例如失谐 −500 MHz 换成 THz 使光频为负、偏移超出 ±1 000 000 THz）：框中保留新单位下的数字，标为无效并写明原因，场景不变，直到下一次编辑；Esc 放弃。
  - 单位随数值保存，都是必需的：`frequencyUnit`、`powerUnit`、`waistUnit`、`intensityUnit`、`dynamics.durationUnit`、热分布初态的 `dynamics.temperatureUnit`、参考能级的 `offsetUnit`。
  - 数值框不接受算式（v3 Field 只解析数字）；频率的"表达式"是基准加偏移，换单位时基准不变，只有偏移的单位改变。
- **按 NA 指定强度**：强度的"指定方式"有三种：局域强度、功率与束腰、功率与 NA。
  - 功率与 NA：输入为功率 P（单位规则同上）和数值孔径 NA（无量纲；原子在真空中，0 < NA ≤ 1，否则标为无效并写明原因）。光束充满物镜的 NA，输出束腰 w₀ = λ/(π·NA)，λ = c/ν 为这束光由其绝对频率得到的真空波长；这是傍轴高斯光束关系，NA 取 1/e² 远场半角的正弦，NA 大时只是近似。局域强度取高斯光束轴上的 I = 2P/(π·w₀²)，与功率与束腰方式相同。
  - 输出束腰和局域强度显示在禁用的数值框里，单位选择器可用（计算值，换单位换算）。激光频率改变时二者随之更新（强度锚点的指纹含功率、NA 与波长）。
  - 切换指定方式保持局域强度不变：目标方式的束腰或 NA 取这束光已有的值（没有时束腰 1.2 μm、NA 0.5），功率由强度反算。数据为 `intensityMode: 'na'` 与 `numericalAperture`；场景校验拒绝 0 < NA ≤ 1 以外的值和缺少 NA 的 NA 方式。

### 6.16 部分达到精度的结果与中间结果（2026-10-27）

- **不扣留算出的结果**（取代 §6.13 中"达不到即失败"的做法）。轨迹的 `populationAccuracy` 带 `sampleErrors`（每个采样时刻一个布居误差上界）、`estimatedMaximumError`（其最大值）和状态：全部 ≤ ε 为 `estimated-converged`，否则为 `estimated-partial`，并带 `reason`。长期布居（`meanHorizons` 的每一项）带 `estimatedError` 和 `withinTolerance`；`status` 仍是物理分类，`not-converged` 只表示没有算出可用结果。这些字段都是必需的：界面与求解器在同一个 EXE 中发布，不保留旧格式。
- **布居演化图**：所有曲线照画；误差超过 1% 的采样（到相邻采样的一半为止）铺浅橙色背景，曲线在那里画成淡色虚线，图例加一项"估计误差 > 1%"。悬停读数在时刻后写该时刻的 ±误差，超出时为橙色并注明。读数放在光标线较宽的一侧，图窄时按那一侧的宽度换行，不盖住光标，指针始终在图上；新的检查点或最终结果替换图时，打开的读数留在原采样上（同一次计算的检查点与最终结果采样相同）。
- **状态栏**：部分达到时加一句，例如"t ≤ 0.021 μs 估计误差最大 1.2%（超过 1%），其余时刻 ≤ 1%"（`accuracy.ts`）；p̄(T) 超出时写"p̄(1 s) 估计误差 0.72%（超过 1%）"。两者同时出现时状态栏写短句"t ≤ 0.021 μs 误差最大 0.61% · p̄(1 s) 误差 0.72%（均超 1%）"，完整的两句在它的悬停提示中，800 px 宽时也放得下一行。
- **每个输出按自己的误差界判断**（2026-10-28）：`estimated-converged` 表示轨迹每个采样点的误差上界都在 1% 内，长期平均的 `withinTolerance: true` 表示它自己的误差上界（含投影到密度矩阵的改变量）在 1% 内；否则分别为 `estimated-partial` 与 false，文字写"超过 1%"。求解器不再有"上界在 1% 内但未确认收敛"的结果（原来的"未确认收敛"已取消）：读取时状态与误差界不一致的结果被拒绝。
- **能级图**："指定时刻"的误差超过 1%，或 p̄(T) 超出时，仍按算出的布居着色；工具栏时刻旁出现橙色"⚠ 估计误差 x%"，能级的悬停文字在数值后写"（估计误差 x%，超过 1%）"。
- **中间结果**：请求带 `stream: true` 时，求解器每到一个检查点发一个 `checkpoint` 事件，内容与最终结果相同，另加 `progress: true`（只求长期布居时是单行 t = 0）；最后的 `result` 是最好的检查点，不带 `progress`。原来的 `asymptotic`（稳态进度）事件已取消。完整请求（轨迹与长期布居同时算）在轨迹的每个检查点发出（2026-11-02 起不再等长期布居算完）：带长期布居已到的程度——它最新的检查点，算完后是它的结果，第一个检查点之前没有 `meanHorizons`；轨迹算完后长期布居的每个后续检查点再发一次，带轨迹的结果。检查点不画出来（2026-10-28）：计算期间图、能级和读数都不变，状态栏只写"布居计算中… · 当前估计误差最大 x%"；最终结果到来时一次画出全部内容，不会出现先显示、后消失的误差标记。界面在后台保留最后收到的检查点：按"停止"后它成为结果，一次画出，按部分达到精度的结果标出各时刻的误差，状态栏写"计算已停止 · 显示最后的中间结果：t ≤ 0.42 μs 误差最大 1%（超过 1%）"（短句；几段时刻时只写段数，如"2 段时刻误差最大 1%"，位置看图中的浅橙色背景；完整的句子在悬停提示中）；求解失败时同样保留它，状态栏写"计算失败 · 显示最后的中间结果：…"。没有收到检查点就停止时，什么也不画，状态栏写"计算已停止 · 修改参数后重新计算"。完整请求在长期布居第一个检查点之前停止时只保留轨迹，长期布居在这组参数下不再请求（停止对它同样有效），能级图的长期布居模式写"计算已停止 · 修改参数后重新计算"。
- **剩余时间**（2026-11-02）：检查点可以带求解器对剩余墙钟时间的估计 `diagnostics.estimatedRemainingMs`（毫秒，有限且 ≥ 0）；最终结果不带，读取时拒绝带它的最终结果和不合规的值，布居与运动的结果相同。布居核心的估计只来自这次运行本身（`pipeline::Progress`）：剩下的求解数乘以这次运行从开始求解以来每次求解的平均用时（含检查点本身的工作），不超过 48 次的求解预算。从第三个检查点起（两个实测的误差估计），剩下的求解数由最大误差估计从第一个实测值（第二个检查点）以来每个检查点的几何平均下降率推出：降到 1% 还要几个检查点，每个 4 次求解；没有下降时按预算剩下的全部求解。在那之前（第一个检查点的估计不是测量，一个变化给不出速率），剩下的求解数是走完极点梯子第一轮的那个检查点之前的求解（稳态列和每个极点各一次：空间第一次含有输出需要的每个时间尺度），至少下一个检查点的 4 次。运行在这个检查点结束时为 0；第一个检查点之前的准备阶段（本征基、显式集、远壳折叠）没有估计。完整请求的估计是两个运行中较大的一个（各自从最新的检查点倒数）；长期布居第一个检查点之前、或它的倒数已经用完时没有估计。这是估计不是上界：接近 1% 时下降变慢的运行比估计的久，只走了一轮梯子就收敛的运行比估计的快（实测：第三个检查点起预计/实际 0.2–1.9，中位约 0.7；前两个检查点 0.4–2.4，亚秒级的运行最高 3.6）。状态栏在"布居计算中… · 当前估计误差最大 x%"之后写"预计剩余约 12 s"，从收到检查点起倒数，数值变化时（至少每秒）更新：10 s 以下按整秒（不写 0 s），1 分钟以下按 5 s，更长按整分钟（"约 2 min"）；估计为 0 时写"即将完成"；倒数到零而下一个检查点还没到时不写剩余时间（估计已过，不再声称），下一个检查点带来新的估计。第一个估计到来之前不写。它在状态栏的最后，倒数时前面的文字不动。
- **详情**：计算详情的"布居误差估计"写最大误差和是否部分超出，其下一行写超出的时刻和求解器给出的原因；有长期布居误差时加"长期布居误差估计"一行。模型说明写明每个时刻的误差和部分达到时的显示方式。

### 6.18 两个时刻 T 一次算出，切换 T 即时显示（2026-10-28）

- **求解器契约**：每次长期平均的计算都给出两个标准时刻 100 ms 和 1 s 的结果（没有 t → ∞），长期平均只有这一种写法：`meanHorizons`，两项，每项 `{horizonUs: 1e5 | 1e6, populations, densityReal, densityImag, estimatedError, withinTolerance, status, reason}`，算出的项 `status` 为 `time-average`（T 时刻的相位平均）。请求的 `meanHorizonUs` 只能是这两个时刻之一（其它值和 null 都报错）；它指明界面当作长期平均读的那一项，诊断里长期密度的数值验证属于这一项。稳态、稳态残差、守恒量个数和"依赖初态"的分类都已取消。原来与这一项重复的顶层字段（`asymptoticPopulations`、`asymptoticStatus`、`horizonUs` 等）已取消。完整请求带 `includeMean: false` 时只返回轨迹（没有 `meanHorizons`）。
- **严格读取**（`solver-client.ts`）：请求了长期平均（算出与否）就必须有 `meanHorizons`，没有请求就不能有；唯一的例外是完整请求在长期布居第一个检查点之前的检查点（§6.16），最终结果没有例外。列表恰好两项，两个 T 各一项（顺序不限）；每项按同一规则读：状态是 `time-average` 或 `not-converged`；算出的项有 32 个概率、复密度（对角与布居一致、厄米、正性子式）、误差上界，且 `withinTolerance` 与"误差 ≤ 1%"一致；未算出的项没有布居和密度。请求的 T 那一项就是结果的长期平均（`mean`）。方法和最慢弛豫时间属于这次计算，两个 T 共用；长期密度的数值验证只属于请求的 T。界面与求解器同版发布，没有兼容旧求解器的路径。
- **缓存**（`current-results.ts`、`solve-plan.ts`、`dynamics-cache-key.ts`）：长期平均按"长期平均的输入 + T"缓存，输入是物理参数与初态（`meanInputsKey`），不含时长、采样点数和 T；轨迹按"轨迹的输入"（`trajectoryInputsKey`：长期平均的输入 + 时长 + 采样点数）缓存。每个结果带来的两个 T 都存入。只保留当前输入的结果：物理参数或初态一变，两个 T 一起作废；时长或采样点数一变，只作废轨迹。回到早先的输入要重新计算。
- **请求**：页面需要什么就只请求什么。长期布居模式（能级图 p̄）只需要 T 时刻的长期平均，其余页面还需要轨迹。缓存里有 T 时刻的长期平均时，切换 T 立即显示，不发请求；改时长或采样点数（以及其它不改变长期平均输入的修改）只请求轨迹（`includeMean: false`），长期平均用缓存中的。都没有时发完整请求；只缺长期平均时发只求长期平均的请求。正在进行的请求若能带来所缺的内容（长期平均的计算带来两个 T），换页面或换 T 不会取消或重发它。
- 其余不变：计算期间不画中间结果，最终结果一次画出；"停止"后最后一个检查点成为结果（它的轨迹，以及在没有最终结果的 T 上它的长期平均，都标为中间结果）；每个时刻的误差标记照旧。

### 6.19 模型范围：警告，不是拒绝（2026-10-28）

- 没有波长窗口：任何波长的激光都可以设置和计算。模型在哪里不代表激光的作用，就在哪里写明，结果照常计算和显示（`spectroscopy.ts` 的 `modelScope`）。
- 两种情形。其一，激光接近 32 态以外能级（6P、nS、nD）的共振：这些能级只作为二阶静态（van Vleck）光移进入 H0，耦合/失谐比 |Ω/2Δ| 超过 1%（`STATIC_MIXING_LIMIT`）或虚跃迁失谐不足 10 GHz（`OUTSIDE_GAP_MHZ`）时，二阶项不再代表它们。这与能级图画静态光移的规则是同一条：打开"显示光移"的这束光在能级图中也不画光移（"离共振太近"）；能级图另有 D 线自己的条件（失谐 ≥ 100 MHz），动力学中 D 线是显式驱动，不需要它。原来动力学在这里拒绝构建模型，现在只在恰好共振、二阶项无定义时拒绝。其二，激光波长短于 5P 的光电离阈值（5P₃/₂ 479.1 nm、5P₁/₂ 473.7 nm，由 Rb 电离能 33 690.8048 cm⁻¹ 减去 5P 能量得到）：光电离不在模型内。
- 显示：状态栏下方一行橙色文字，每页都在："超出模型范围（结果照常给出）："后接每条说明，点名激光与原因，例如"「蓝光」的波长 450 nm 短于 5P₃/₂ 和 5P₁/₂ 的光电离阈值（479.1 nm、473.7 nm）：光电离不在模型内。"或"「telecom」离 4D5/2 的虚跃迁失谐只有 4.69 GHz（不足 10 GHz）：32 态以外的能级（6P、nS、nD）只作为二阶静态光移进入模型，这里超出它的适用范围。"同一频率的几束光作为一个载频一起判断、一起点名。详情页"当前计算"中重复这些说明；没有这些情形时这一行不出现。

### 6.20 运动：光镊中单个原子的三维运动（2026-11-03）

取代原来的 1D、2D 径向与"3D（半经典）"三种运动轴（2026-11-02）：运动只有一种，三维，半经典。

- **默认打开**：新场景与启动时的默认场景运动都打开（`dynamics.motion.enabled`），布居演化计算光镊中单个原子的内态与三维运动一起演化；只有操作者关闭"运动"时才只算内态，原子静止于焦点。示例中有光镊的（光镊 + 探测光 + 回泵光、光镊 · 3D PGC）运动打开；只讲内态物理的示例（单束光、循环跃迁、Rabi、光抽运等）关闭光镊，运动也关闭（运动需要势阱）。
- **光镊**：运动的势阱是操作者指定的光镊（§6.21）。没有光镊，或光镊关闭、强度为零、按局域强度给出（平面波）时不计算，状态栏（错误）与图区写明原因并点名（`tweezer.ts` `tweezerRefusal`），例如"运动需要光镊：请在一束激光的参数中打开“设为光镊”，或在布居演化页关闭“运动”。"或"运动需要光镊：光镊「光镊」已关闭。"
- **设置**：布居演化页设置区的"运动"一组：开关"运动"，打开后有"初始温度"与"计算设备"，没有"运动轴"。"初始温度"是 v3 Field（K / mK / μK，≈ 规则；按 §0.4 换单位保留数字，存为 μK 与单位），各轴相同：动量为 Maxwell 分布，位置为初态势阱中的 Boltzmann 分布，各轴再按谐振子的热 Wigner 分布放大到 T* = (ħω/2k_B)·coth(ħω/2k_BT)。"计算设备"是分段控件 GPU · CPU，默认 GPU。关闭时这两行不显示，设置保留在场景中。三组设置并排放不下时换行。
- **计算设备**：请求选项 `device`（"gpu" | "cpu"，只与运动同在；缺省为 GPU）。结果的 `diagnostics.device` 是实际所用的设备；不是所选的那个时 `diagnostics.deviceNote` 写明原因，例如"找不到 NVIDIA 驱动（nvcuda.dll）：本次在 CPU 上计算""NVIDIA 驱动太旧（CUDA 11.8；需要 CUDA 12.0，即 R525 / 527.41 或更新）：本次在 CPU 上计算""GPU 正在首次准备（驱动编译内核，新版本首次使用时一次）：本次在 CPU 上计算"，状态栏在"运动已计算"之后写出它，详情的计算详情也写出。设备是场景的一部分，进入轨迹的缓存键：换设备即重新计算。
- **结果视图**：标题行的分段控件"布居 · 温度与 n̄ · 动量分布 · 位置分布"只在运动打开时出现；"线性 / 对数"只用于布居。损失概率以外的量都是仍在光阱中的原子的。
  - 布居：引擎给出仍在光阱中的原子的 32 态布居 p_i 与损失概率 L。读取时（`solver-client.ts`）每个态换成原子在该态且仍在光阱中的概率 p_i·(1 − L)，所以 32 个态与"丢失"L 之和为 1。"丢失"是一条可选的曲线：观察曲线中的"丢失（原子离开光阱）"，场景中存为 `monitoredGroupIds` 的 `loss`，画成中性灰色；"初末各 3 态"把它与各态一起排序。能级图"指定时刻"着色用的也是 p_i·(1 − L)，工具栏的合计在 F=1、F=2、激发态之后加"丢失"。误差标记按方法自己的目标（两倍标准误差对 5%），图例写"估计误差 > 5%"。

  - 验证范围：结果对每个采样标明是否在 k_BT ≥ 4ħω（各轴，solver-types.ts `SEMICLASSICAL_REGIME`，与 motion-3d `CLASSICAL` 同一个数）之内。范围之外的采样在每个随时间的图上铺浅灰背景（#ecebea，悬停提示"半经典方法的验证范围之外（各轴 k_BT ≥ 4ħω 才验证过）：仅供参考"），图例加一项"验证范围之外（k_BT < 4ħω），仅供参考"，悬停读数在时刻后写"· 仅供参考"，分布图例中的时刻写"（仅供参考）"。状态栏写"运动已计算 · t ≥ 0.4 ms 起有时刻低于验证范围（k_BT < 4ħω），仅供参考 · 耗时"，全程在范围外时写"全程低于验证范围……"。范围用引擎自己的 T 判断：方法偏冷时它低于量子的 T，标记只会提前、不会推迟。
  - 近似账目：结果带 `diagnostics.approximations`：`budget`（先验近似可用的误差预算，方法布居目标的一部分）、`used`（已用）、`items`（每项近似的 `label`、相对误差估计 `estimate` 与引擎的处理 `action`）和可选的 `flagged`（有输出时刻的总估计误差超出方法目标时的说明）。`flagged` 像验证范围一样写出：状态栏（警告）、每个视图的图例（警告色）与详情。详情的计算详情列出所用设备（与 `deviceNote`）、轨迹数与时间步长、"近似误差"（合计 `used`，最大的一项按它的 `label` 写出、其余各项相加，对布居目标 `populationAccuracy.requestedTolerance`；没有 `flagged` 时写"未超出"，有时写"超出目标（见下）"（`flagged` 的说明写在下一行：某些时刻的总误差超出目标，或光在原子所到之处接近共振），例如"合计 1.3%（消去激发态 1.1%，其余 5 项 0.21%），布居目标 5%，未超出"）、"取舍预算"（`budget`，后注"折叠或保留、平面波或强度维度、一阶或精确多普勒"：先验近似按它取舍，它不是合计的上限）和账目表（近似、估计误差、处理；误差以百分数写出）。
- **能级图的 p̄(T)**：长期布居只是内态的，相当于原子静止于光镊焦点。运动打开时，工具栏的模式写"静止原子 p̄"（悬停写明"原子静止于光镊焦点时内态的长期布居（运动只进入时间演化）"），状态栏写"静止原子的长期布居 p̄(1 s) 已收敛"，详情与模型说明同样写明；它的输入与缓存不变（运动的开关、设备与光镊都不进入它的键）。"指定时刻"读运动的轨迹。
- **默认时长**：100 μs，1000 个采样（types.ts `DEFAULT_DURATION_US`）：默认场景中探测光的光抽运与默认光镊的几个径向阱周期（径向 74.6 kHz，约 13 μs 一个；轴向 11.9 kHz）。启动时能级图只求内态的 p̄(T)（与运动无关，和以前一样快）；打开布居演化时运动在 CPU 上约 0.3–0.4 s 算完（16 核，512 条轨迹，dt 0.1 μs，实测 362–382 ms 含通信）。
- **请求只带需要的运动**：运动只随单独的轨迹请求（`includeMean: false`）发出；能级图的 p̄(T)（只求长期平均的请求）是内态的，运动打开时也不带运动（solver-client.ts `motionOf`）。
- **请求与缓存**：运动的轨迹单独请求（`includeMean: false`）。请求选项带 `motion: {axis: '3d', temperatureUK}` 与 `device`。模型带 `motion` 块（full-master-model.ts `MotionModel`）：`axis` 总是 "3d"；`trapBeamId` 是光镊的 ID（必需）；坐标系是实验室的 x、y、z（motion.ts `MOTION_FRAME`）；每束驱动光有 `id`、`name`、`direction`（单位波矢）、`waveNumberPerUm`、`waistUm`（只有高斯光束有：按功率与束腰或按数值孔径给出强度的光，焦点在原子处的 1/e² 强度半径；按局域强度给出的光是平面波，没有）、`intensityMWcm2`（原子处，高斯光束为峰值）、`frequencyIndex`、原子处的同向与反向旋转耦合和经 32 态以外能级的静态光移；模型块另带没有光束的 H0、各态的帧频率、实验室坐标轴上的笛卡尔辐射算符、质量与磁场。有束腰不再意味着光镊：光束形状在哪里起作用由引擎逐束判断。轨迹的缓存键含运动、设备、光镊与各束光的束腰；运动关闭时这些都不进入它。
- **结果契约**：`motion` 块（rust-solver/src/motion3d_adapter.rs，solver-types.ts `readMotionResult` 严格读取）为 `{axis: '3d', temperatureUK, temperatureErrorUK, temperatureTotalUK, temperatureTotalErrorUK, meanVelocityMps, meanOccupation, trapFrequencyKHz, momentum, position, lossProbability, classical, trajectories, timeStepUs}`：T、T 的标准误差、⟨v⟩、n̄、阱频与分布按轴（`{x, y, z}`）给出，T、标准误差、⟨v⟩、n̄ 每个采样一个数，阱频是正数；总温度及其标准误差每个采样一个；分布在递增的采样上给出，包含末时刻，每个分布是网格上的概率；损失概率每个采样一个、在 0 到 1 之间且不减；`classical` 每个采样一个布尔。诊断信息另有 `device`（必需）、`deviceNote`（可选的非空文本）与 `approximations`（必需，格式见上）。`populationAccuracy` 的 `requestedTolerance` 是 0.05，`sampleErrors` 是各采样布居与损失的两倍标准误差中的最大值；布居的每一行投影到概率单纯形上（控制变量的估计无偏，接近零的布居可能略低于零），投影的改变（各态与各组之和的最大变化）加进该采样的误差，`traceError` 与 `initialStateError` 仍是投影前各行的（迹的检查对引擎的原始行进行，系统性的迹误差照样拒绝）；t = 0 一行是请求的初态（布居，以及各轴 T：初态势阱中的热 Wigner 温度，⟨v⟩ = 0；总温度精确、误差为 0），误差为 0；统计目标从 t = 0 之后的采样算起。没有运行报告（`running`）：只有原来的 2D 引擎发它，已与 2D 引擎一起删除。
- **求解**：rust-solver/motion-3d，经 motion3d_adapter.rs 转接。1D 引擎（motion-core 的 GMW-o1）与 2D 引擎（motion-gpu）已删除，最后包含它们的版本是 v2026.11.2.6。
  - 方法：每条轨迹是一个经典质点 (r, ħκ) 和一个子空间内的基态内态 ψ（motion-3d `ground` 消去激发态的生成元）。跳跃之间 ψ 按非厄米 H_eff 演化（等待时间展开），力是 Ehrenfest 力 −∇Re⟨ψ|H_eff|ψ⟩。跳跃时：光子按频率分道（落入哪个子空间、哪组光），按 Σ‖u_a‖² 抽样；方向按偶极辐射方向图精确抽样，反冲 −ħk n；吸收的光按各束光的份额抽一束，反冲 ħk_l，再加这个光子精确的条件平均动量与所抽平均之差。
  - 耦合与子空间：基态之间的每个耦合——两个"载波, 态"通道之间的拉曼项、同一超精细能级的塞曼子能级之间的光耦合、同一个态上两组光的拍频、H 的静态耦合、一次跳跃的两个光子——按远失谐分量的同一规则判断：频率间隔（含塞曼与光镊的态相关移动，取阱内最坏），大小为阱内超算符的界，m² 不超过预算且满足频隙规则时二阶折叠（van Vleck 移动；经单束光的路径制入表，经多束光的四阶项略去并记入账本），否则显式保留。显式耦合连起来的态组成子空间：B ≈ 0 时一个超精细能级（lin⊥lin 下按 m 的奇偶分开），大磁场下单个子能级（速率方程极限），只有拉曼共振的通道把 F = 1 与 F = 2 连在一起（Λ、EIT、灰色粘团）。子空间的转动坐标让最强的保留耦合静止，其余拍频显式。子空间是态的列表，以后激发态也可以按同一规则加入。
  - 光场：每束光都是完整的 3D 光束——有束腰的是带 Gouy 相位的傍轴高斯光束（场按精确的高斯分布），其它是平面波。光镊（trapBeamId）总是表的一个强度维度；其它高斯光只有在原子的热范围内（势能 ln(1/预算) k_BT 之内）强度下降带来的光移误差（相对生成元的尺度）超出预算时才加一维（最多共三维，误差大的先加），否则按峰值强度取光移，沿轨迹的误差记入账本。对强度制表，三次插值，网格加倍到插值误差不超过预算的先验份额（加倍后的网格沿用粗网格的节点，每个节点只算一次）。每组表只存它的条目（该组的剩余拍频所到的矩阵元及其 van Vleck 路径的位置），其余处为零，不存也不插值；力由每对表在条目上的值与斜率在步中点的内态上求二次型得到，不再先合成三个梯度矩阵。
  - 积分：沿光镊的主轴精确转动谐振部分，其余（非谐部分与光的力）在半步处踢；ψ 的指数取 Taylor 级数。跳跃落在一步之内时，这一步重做到跳跃时刻，跳跃之后从新的内态继续，力跟随跳跃前后的内态。
  - 步长：先跑几条试探轨迹取样态，对每个样态比较一步 dt 与两步 dt/2（不跳跃）。满足目标要求（4/3 倍的）差别都在各自的份额之内：内态布居之差累计到两次跳跃之间（试探轨迹的平均等待时间）不超过先验份额 × 5%——上界是一步之差乘以这段时间的步数；冲量与摩擦满足时还直接测：从每条试探轨迹取一个样态，不跳跃地以 dt 与 dt/2 走过这段时间（最多到总时长），子空间布居之差的最大值取平均再加两倍标准误差（灰色粘团中原子在暗态里等 50–140 μs，上界高估几倍）；冲量与摩擦（机械能的平均变化，保守力不改变它）的相对误差不超过先验份额 × 10%。都按 dt² 变化：不满足时按超出的平方根缩小步长，有余量时同样按平方根放大（任意倍数），每个新步长都再检验，直到建议的步长已检验过——先只用布居的上界，再从按上界满足目标的最大步长出发用实测的布居误差。检验过且满足目标的步长都是候选，取预计代价最小的：每个采样间隔的工作量（计时：从这些样态出发，每个候选背靠背走一个采样间隔的真实步，含跳跃与跳跃重做的步，取各样态比值的中位数）乘以统计所需的轨迹数。轨迹的离散度要一批之后才知道，但不论它是多少，候选所需的轨迹数与按上界取的步长之比不超过两个目标中（该步长的余量 / 候选的余量）² 的较大者，余量是目标减去先验估计与步长偏差；候选偏差较大时对决定轨迹数的那个目标精确。只有在工作量取计时的上置信界时仍更省的候选才取代按上界取的步长，计时的噪声不会让步长在代价相同的候选之间来回变。步长大并不总是更省：偏差占掉统计的余量，每步的工作量也随 dt 增加（指数的子步、跳跃重做的步）；3D PGC 与四面体 MOT 的候选代价相差几个百分点，D1 灰色粘团实测布居误差使代价减半。都不满足目标时取最后检验的。
  - 一阶多普勒：光子振幅取吸收动能移的一阶；每步的 (kv/σ)²（各近共振光的 (w_l/σ_c)²，w_l = ħk_l·κ/m + ħk_l²/2m 是吸收第 l 束光的动能移，σ_c 是其载波最近的激发态极点）超过预算剩下的部分时，这一步的跳跃用精确响应。
  - 损失：原子的机械能——动能加上当前内态在光镊中的势能（Re⟨ψ|H_eff|ψ⟩ 减去光镊关掉时的同一量，远离光镊为零）——为正时算作丢失。
  - 近似账本（`diagnostics.approximations`）：预算 = 先验份额 × 布居目标 = 0.5%，详情中写作"取舍预算 0.5%"；"近似误差"一行是各项之和（含 η²）对布居目标。各项：远失谐分量的折叠（Σm²）、基态耦合的折叠（Σm²）、略去的四阶 van Vleck 项、按峰值取的高斯光、插值表、消去激发态的 η²（沿轨迹测的平均激发态布居；对共振探测光与布居核心比较：光泵浦的布居误差 0.4–1.1 η²，循环跃迁 2η⁴）、一阶多普勒 (kv/σ)²。预算只用于决定（折叠或保留、平面波或强度维度、一阶或精确多普勒）；η² 只计入总误差。消去激发态的先验界：原子所到之处（光镊主轴上 ±热范围内的强度）各基态的激发态权重 Σ_l‖R_l[:,b]‖²（各束光在峰值、不相干相加）的最大值，超过布居目标时设置 `flagged`（"光在原子所到之处接近共振：消去激发态的先验界（基态的激发态权重）达 X%（目标 5%），近共振处消去激发态不成立"），沿轨迹测得的 η² 在近共振处会漏掉它（D1 灰色粘团在光镊中心 +34 MHz 的 D1 光移下 +25.9 MHz 的光变成红失谐；补偿光移后的 GMD1C 为 1.6%，3D PGC 0.6%，不标记）。
  - 统计与标记：轨迹分批，每批分成 8 条轨迹一组（CPU 的一个任务、GPU 的一个 block），组内拉丁超立方取初态，分组刀切法估计标准误差。所有批次的组一样大，每条轨迹在方差中的份额相同，一批的误差预测的所需轨迹数对之后的轨迹同样成立；8 条一组保留了拉丁超立方的大部分收益（早期 T 所需的轨迹比单条一组少 10–40%，再大的组收益很小），刀切的组数随轨迹增加。第一批每线程两组；之后每批取预计还需的轨迹数（当前误差所需减去已算），至少为设备的宽度，至多与已算的一样多：所需轨迹数是许多输出的估计误差中最大的一个，组少时偏高，所以最多按它外推到已算轨迹的两倍。预测之上不加余量：多一批只多设备的收尾与一次统计，约几条轨迹的时间，按估计自身的噪声加余量却要多算百分之几十的轨迹。（轨迹逐条交给空闲的线程，每组按轨迹顺序累加，各线程在一条轨迹的时间内一起结束，结果与线程无关；T、⟨v⟩、n̄ 取每个原子一个阱周期内的平均：每一步只计入它所在的输出区间一次——区间的累计和，以及窗口边缘在区间内的固定位置两侧的部分和——每个窗口由两个累计和之差与两端的部分区间得到，每步与每个输出的工作量都与窗口长短无关），每批的结果作为检查点流出，带剩余时间估计。每个时刻的总估计误差 = 账本合计（该时刻的 η²、平均 (kv/σ)² 与沿轨迹的高斯光误差）+ 步长偏差（所取步长的布居与运动比值乘以各自的份额：布居先验份额 × 5%，T 先验份额 × 10%；布居实测处取实测的上置信界）+ 两倍标准误差，布居对 5%（绝对），T 对 10%（相对，只在验证范围内）。轨迹一直算到总误差在目标之内（最多 16384 条）；仍超出目标的时刻才设置 `flagged`，写明时刻与各部分（"……估计误差超出目标：布居误差最大 X%（目标 5%；近似与步长 Y%，其中消去激发态 Z%；统计 W%）"）；检查点只按先验部分标记。
  - 控制变量：每个输出的 κ² 与布居用均值精确已知的控制变量来估计（motion-3d `control.rs`、`stats.rs`）。
    - 谐振孪生（T）：每条轨迹的初始 r₀、κ₀ 只在光镊的谐振部分中运动，它在该输出的 T 窗口上的 κ²，减去 κ₀ = 0 时的同一量；它的均值由初态动量的协方差精确给出，与 r₀ 的分布无关。总是计入，每个输出只需几次乘法。原子还在谐振阱里运动的早期，它与原子自己窗口上的 κ² 几乎一致；光与非谐部分随后使两者失去相关。
    - 静止孪生（布居）：同一条轨迹不动地放在光镊强度等于试探轨迹平均强度的点上，与原轨迹共用同一初态内态、同一阈值与跳跃随机数（跳跃先抽类别、下一个阈值、偏振与吸收的光束，最后才是方向的拒绝采样，所以孪生的阈值与选择不随方向采样的次数错位）。它的布居均值是该点消去激发态后的主方程：取引擎在该点的生成元的厄米部分与引擎的跳跃算符，耗散取这些跳跃自己的 Σ L†L，再取超算符的指数；只在生成元没有剩余拍频时使用。引擎的耗散来自响应的表，跳跃取光子并含反冲的一阶，二者相差约散射率的 1e-4。若用一者的耗散配另一者的跳跃，主方程会漏掉迹，每一行布居的和随之偏离 1，均值也不再精确。按上面的构成，孪生的展开恰是这个 Lindblad 方程：均值精确，迹恒为 1，每条轨迹的修正之和恒为 0。孪生的引擎在该点预先算好生成元、跳跃算符与半步传播子，每步只做两次小矩阵乘法，代价约为一条轨迹的 4–10%。第一批里运行；按第一批估计的布居所需轨迹数乘以 (1 + 它的代价)，比不用时少才保留（它只降低布居的误差）。光场在运动尺度上变化（PGC、灰色粘团）时两者不相关，因而不保留。
    - 估计量：每个输出上原子的量减去 β 乘以控制变量与其精确均值之差。β 是对控制变量的回归，用到目前为止的全部轨迹（布居共用一个 β，保持总和）；刀切法去掉一组时 β 不变，标准误差是修正后的量在各组间的离散，停止规则用的就是它。若每组都重算 β，早期输出上 β 只靠少数已跳跃的孪生，会在组间大幅摆动，反而淹没误差。不相关处 β ≈ 0。
  - 设备：`options.device` 为 GPU（缺省）时轨迹在 NVIDIA 显卡上计算（motion-3d `gpu`，内核 kernels/motion3d.cu），为 CPU 时在处理器上。两者是同一个求解：模型、近似账本、试探轨迹与步长选择都在 CPU 上以双精度完成，每条轨迹的初态在 CPU 上抽取，随机数是同一组 Philox 流，统计、分组刀切与停止规则相同。GPU 内核每条轨迹一个 warp、每个任务（同组的至多 8 条轨迹）一个 block，做 CPU 引擎的每一步（谐振部分的精确转动、由表插值的 H_eff、其指数——与 CPU 同一 Taylor 截断规则，按矩阵计算——、Ehrenfest 力、ln‖ψ‖² 越过 ln θ 的时刻、重做到该时刻）、跳跃（类别、偶极辐射方向图、偏振、反冲、精确响应用 LU 求解）、损失判定、读出与各轴一个阱周期的窗口：局部运算单精度，累积与判定（时间、位置与动量及其转动、ln‖ψ‖²、随机数与按它们的选择、窗口与所有求和）双精度；每个 warp 独立地走完一次 launch 的各输出区间，把每个区间的记录写进自己的槽，launch 结束时 block 再按轨迹顺序对各区间求和——与 CPU 的任务内顺序相同，结果可重复；warp 每次 launch 只等一次最慢的轨迹，而不是每个输出等一次。控制变量在两种设备上相同：GPU 上每个 warp 在同一输出区间里先推进轨迹，再推进它的静止孪生（同一跳跃随机流，预先算好的半步传播子、跳跃算符与读出），谐振孪生的控制量在每个 T 窗口结束时由初始 r₀、κ₀ 与该输出的 A、B 算出；孪生所占的时间（时钟周期之比）给出保留静止孪生的代价。一批至少与设备一次能同时计算的一样宽：CPU 每线程两条轨迹；GPU 每个驻留的 block 一组（一波），批次取整波，所以 GPU 上第一批通常就是最后一批。
  - GPU 的要求：计算能力 7.5（Turing）或更新的 NVIDIA 显卡、CUDA 12.0 驱动（R525 / Windows 527.41）或更新。EXE 内嵌 compute_75 的 PTX（固定版本的 NVRTC 12.0 编译，motion-3d/scripts/ptx.ps1；一个测试检查 PTX 与源码的哈希），运行时加载 nvcuda.dll，只用驱动 API，不带 CUDA 运行库。没有可用的显卡或驱动、驱动太旧、显卡太旧或模型超出内核（子空间多于 8 个态等）时在 CPU 上计算，`deviceNote` 写明原因；计算中 GPU 出错则这次求解在 CPU 上重做并说明。环境变量 `ATOM_HIDE_NVCUDA` 模拟没有驱动。
  - GPU 的启动：工作进程只建一次 CUDA 上下文并保持到退出；轨迹通道的工作进程启动时（`warmup` 带 `lane: "trajectory"`）就在后台建立，求解开始时也会启动它。驱动在新版本的内核首次使用时编译 PTX（本机约 7 s，之后读驱动的缓存约 10 ms）；求解最多等 GPU 启动 2 s（`START_WAIT`），仍在编译就在 CPU 上计算并说明，不让第一次求解卡住。
  - 拒绝：只计算 3D 运动（运动轴需为 3d）；光镊需要束腰，不约束原子时"光镊不约束原子：……"。
  - 验证：原子固定在焦点时对布居核心的内态求解（200 μs）：3D PGC 示例消去后的主方程最大 |Δp| 0.0027，Λ 示例（光镊 + 探测光 + 回泵光，从 |2,0⟩ 与 |1,0⟩）0.0019 与 0.0018，轨迹在 2–3 倍标准误差内。3D PGC 示例 10 ms 的 T 与 v2026.11.2.6 在标准误差内一致（平台平均 24.8/6.5/10.7 μK 对 24.1/6.4/10.5 μK）；半步长对比的步长偏差约 1%。默认场景与 3D PGC 不标记；饱和的共振探测光（1 mW/cm²）标记（布居总误差约 27%，主要是 η²）。验证范围（点粒子没有零点运动）对 1D GMW 参考的测量见 solve.rs 与 v2026.11.2.6。
  - 动量扩散（2026-11-03）：在固定点上，这个方法的动量扩散只有消去激发态后二阶展开的精确值的一部分——Ehrenfest 力把基态叠加中的偶极力涨落平均掉了，按光束抽取的吸收冲量也不带跳跃后内态的关联：lin⊥lin 焦点处约 0.23–0.27，3D PGC 在 40 μK 的热分布上平均约 0.9，15 μK 约 0.5–0.7。按二阶 Wigner 展开逐条轨迹带一个动量—内态关联矩阵 M（漂移 tr 𝒜(ρ̃)、dM/dt = ℒM + 𝒜(ρ̃) − tr 𝒜(ρ̃) ρ̃、协方差率 2 tr 𝒜(M) + 𝓑 的高斯噪声）的做法在给定路径上与精确矩一致（静止 0.6% 内，0.04 μm/μs 匀速 2.4% 内），但不能用于光镊中自由运动的原子：自由运动时 M 会剪切成位置—内态关联，经力的梯度反作用（Sisyphus 摩擦的一部分），这个做法丢掉了它；方差下降时高斯噪声也跟不上。TW2 在 1 ms 时被加热到 174 μK（GMW 参考 14.6 μK），因此没有采用（研究分支 claude/motion3d-m-scheme）。光镊中这个方法对 1D GMW 参考的 T（原子在过焦点的线上，2048 条轨迹，dt 0.2 μs）：加热的 TW1 在 10 ms 内偏高 2–6%；冷却的 TW2 在 1 ms（约 3ħω）偏低 6%，2–3 ms 偏低 23%，更低温时偏低更多（验证范围之外）。
  - 实测（16 核笔记本）：3D PGC 示例 10 ms、1001 个采样 17–21 s（512 条轨迹，dt 0.227 μs；v2026.11.2.6 为 21.7 s、509 条，dt 0.0935 μs），T 与布居在标准误差内一致；Λ 示例 1 ms 约 0.8 s。

### 6.21 光镊：操作者指定（2026-11-03）

- **数据**：场景的 `tweezerId`（可选）是光镊那束激光的 ID；没有它即没有光镊。一个场景至多一束光镊：把另一束设为光镊即改为它（`tweezer.ts` `setTweezer`）。任何一束光都可以，反射光也可以；指定只说明哪一束是势阱，不改变光束本身。场景文件校验它是场景中一束激光的 ID。删除光镊（或删除它所属的源与反射光）时一并取消（`keepTweezer`），删除前的确认写明"删除后运动没有光镊，需要另设一束"。
- **默认与示例**：默认场景的 852 nm 光镊已指定且打开；"光镊 · 3D PGC"与"光镊 + 探测光 + 回泵光"的光镊也已指定。"光镊 · 径向 1D PGC"已删除。"光镊 + 探测光 + 回泵光"是拉曼共振的 Λ：默认光镊（852 nm，4 mW，束腰 1.2 μm，沿 +x）中，探测光在 F=2 → F′=2、回泵光在 F=1 → F′=2 上（自由空间共振），两束沿偏置磁场 +z（3 G），各 1 mW/cm²；|2,0⟩，30 μK，三维运动，1 ms，1001 个采样（examples.ts `LAMBDA_TWEEZER`），打开时显示布居演化。早先按"按功率与束腰或数值孔径给出强度的光就是聚焦光"认定光镊的规则已取消：新激光默认就按功率与束腰给出（§6.22），这些光都是高斯光束，但不是光镊。
- **界面**：
  - 场景列表：光镊名字后有"光镊"徽标（浅底小标签，名字过长时先省略名字）。
  - 检查器：每束光（反射光也是）的第一节"运动"只有一个开关"设为光镊"（悬停说明：运动以这束光为光镊，原子在它的焦点处；一个场景至多一束光镊，打开即取消另一束的光镊身份；光镊须按功率与束腰或功率与数值孔径给出强度）。开关下一行：这束光是光镊而不能约束原子时（关闭、强度为零或是平面波）用警告色写明原因；另一束是光镊时写"现在的光镊是「光镊」。"。
  - 方向与偏振：光镊画成在原子处聚焦的光束，光束在原子处收成细腰、向两端张开（示意，不按比例）；图例中它的名字后有同样的徽标。
- **导出**：运动的模型块带 `trapBeamId`（§6.20）；内态的模型与它无关。

### 6.22 新激光：按功率与束腰（2026-11-03）

- 场景面板"激光"的"＋"加的激光（types.ts `newLaser`）按"功率与束腰"给出强度：50 μW、束腰 1 mm（types.ts `NEW_LASER_POWER_MW`、`NEW_LASER_WAIST_UM`，单位 μW、mm，强度读数 mW/cm²），原子处 I = 2P/(πw₀²) ≈ 3.2 mW/cm²，约为 D2 循环跃迁饱和强度的两倍：冷却光或探测光的典型值，束腰是这类光束毫米量级的尺寸。频率仍是所选 D 线的 F=2 → F′=3（D1 为 F″=2），沿 +x。
- 这样新光是焦点在原子处的高斯光束（运动中带它的光束形状，毫米束腰对原子的运动范围几乎是平面波），不是光镊；光镊由操作者指定（§6.21）。仍可在"指定方式"中改为局域强度（平面波）。默认场景与示例中的光照旧（探测光按局域强度，光镊按功率与束腰）。

### 6.23 反射光（2026-11-02）

一束光可以加一束"反射光"：远处一面垂直于光束的反射镜把它沿原路反射回来（`reflection.ts`）。

- **数据**：反射光是一束激光，多一个 `reflection: {of, reflectivity, phaseDeg, quarterWave}`——源激光的 ID、反射率 R（0–1）、反射光在原子处相对源的光学相位 φ（°，由反射镜的距离决定）、是否双次通过 λ/4 波片。只有反射镜（和名称、读数单位）是它自己的；其余物理参数在场景解析时（`resolveSceneFrequencies` 之后的 `resolveReflections`）由源算出，所以总随源改变：
  - 频率：跟随源 +0 MHz（同一载频，逐位相同）；开关、"显示光移"与能级图参考态同源（源关闭即没有反射光）。
  - 方向：与源相反——同一参考轴，偏移 (180° − θ′, φ′ ∓ 180°)（与"沿 −B"同一写法，`direction.ts` 的 `oppositeDirection`）。这个坐标系是源的坐标系绕自身 x 转 180°：x 不变，y 与 k 反向。
  - 强度：功率与原子处强度为源的 R 倍（取源的精确强度乘 R），束腰或 NA 与源相同：平面波仍是平面波，聚焦在原子处的光理想化为反射后重新聚焦在原子处（相当于反射镜前有透镜或用曲面镜）。
  - 偏振（物理约定见 `physics.ts`：E ∝ cos χ u + i sin χ v，v = k × u）：源的主轴 u 在反射光坐标系中是 ψ′ = −ψ。普通反射镜在实验室中保持电场不变（整体相位并入 φ），所以 χ′ = −χ：相对自身 k 的旋向反转（σ⁺ 回来是相对自身 k 的 σ⁻，相对原来的轴仍驱动 Δm = +1）。双次通过快轴沿 u 的 λ/4 波片使 v 分量反相，实验室中沿同一椭圆反向旋转，χ′ = χ：相对自身 k 的旋向保持（σ⁺ 回来仍是 σ⁺，即 MOT 的回反射）。线偏振两种情况都不变。初相位为源的初相位加 φ。
- **约束**：反射光计入 8 束激光的上限；一束光至多一束反射光；反射光不能再被反射；任何频率都不能跟随反射光（它没有自己的频率，跟随它的源）。删除源时一并删除反射光；删除反射光不影响源。
- **场景文件**：版本不变（`reflection` 是可选字段，旧文件照常读入）。反射光像其它激光一样写出全部字段；读入时严格校验反射镜（源存在、不是反射光、只有一束、R 与 φ 在范围内），并按源重新算出它的光束，文件中写的派生值不起作用。
- **导出**：解析后的反射光就是一束普通的光：主方程与运动都不区分反射光。同频的两束光共用一个相位坐标，在原子处相干叠加。
- **界面**：
  - 场景列表：反射光紧随其源、缩进，符号为源的身份色的 ↩，第二行写反射镜："R 50% · λ/4"（相位与激光的初相位一样只在检查器中）；它没有自己的开关，源关闭时一起变灰。
  - 源的检查器："传播方向"一节有"添加反射光"（达到 8 束时禁用并说明）；已有反射光时改为"选中反射光"，并注明这束光有反射光。
  - 反射光的检查器：顶部"↩ 反射自「源」"，源的名字可点击选中源；"反射镜"一节可编辑反射率 R（%）、相位 φ（°）和"双次通过 λ/4 波片（MOT 常用圆偏振）"开关；"由「源」决定"一节灰色只读：频率（与源相同）与 ν、方向（与源相反）与实际方向、强度（及功率、束腰）、ψ、χ、σ⁻/π/σ⁺ 与初相位；最后是"解除关联"：变为独立的激光，保留现在的光束，频率按源的定义写出（同一载频），并移到列表末尾（其它激光的身份色不变）。
  - 身份色：反射光与源同色；它不占身份色序号，加或删反射光不改变其它激光的颜色。
  - 方向与偏振：反射光画成虚线，在源的光线旁（偏向相机看得到的一侧；两束都过原子）从反射镜返回；反射镜是源箭头之外横跨两束光的小方板，标"镜"。选中其中一束时另一束一起突出显示并标出名称；偏振椭圆按反射光自己的偏振画出。图例中反射光的色块为虚线。
