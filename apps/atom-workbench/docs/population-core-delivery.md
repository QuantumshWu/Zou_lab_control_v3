# Atom Workbench：CPU 布居求解器交付简报

**当前单 EXE 已构建，短时验收有结果，但四光长时性能仍未解决。** 默认目标为概率尺度上的绝对误差 **0.005**，测试档为 **0.001 / 0.005 / 0.02**，不会因计算困难静默放宽。以下是实际完成情况，不宣称达到性能极限或普遍 1–2 秒。

## 已采用的算法与提速来源

物理输入仍由现有 TypeScript fullModel builder 产生。新 Rust core 保留该 Model 的全部 Hamiltonian 与 collapse operators，计算中不按光束名称、F 标签或失谐大小删除耦合。既有模型的物理约定继续适用，例如远失谐背景包含 Stark 项而未加入其散射；本次数值改造没有扩充这些物理假设。

主要节省来自减少完整任务中的重复工作，而非减少物理态数：

- 可逆数值坐标与 Hermitian/Fourier 实坐标减轻快速相干负担；32 维 Hilbert 分解加低秩反馈作为预条件器，生成较小的 rational trial space。
- 每个新方向仍计算完整原 E/F。扩 Fourier 域时精确复用本请求的旧图像，只补新增行；连续小系统 Gram 只用于选择修正方向。
- 工作区增量保存投影矩阵和观测列，Rust 内核共享系数并批量执行，避免反复重算、复制及 Python 调度。

正式停止规则使用实际基底扩张、相邻 Fourier 域比较及固定数值检查。只有原算子支持严格为零频率时，才省去域比较；零填充后的相同曲线不算新验证。

返回资格为 **estimated-converged（经验性收敛）**，不是严格误差界。初态、trace、有限数值与概率范围的检查独立保留。若对人口输出做概率约束投影，其逐态及组布居改变量计入同一误差预算；这不代表原密度矩阵已经修复或通过 PSD 证明。请求完整 density 时保留原有一致输出路径，不把修正后人口与未经修正的 density 混装。

## 用户输入与路线取舍

按用户后来明确的工作流程，目标改为通用完整 Model、默认 0.005、三档精度和实际 EXE 的 200 点短时/长时测试；停止以 10 倍提速为硬目标。输入包含 1–4 近光与远失谐背景，并有偏离轴向的几何、偏振和磁场。光束数不等于独立拍频轴数，不能据此特判封闭系统。修改光场建立新请求，只在请求内复用算子工作，不使用历史答案、基底或参考轨迹作种子。

原周期路径保留：单独立拍频的两光短时用例通过完整周期 CPTP 矩阵及独立网格比较，约 2.3 s，已有成熟数值检查，没有理由强制换成较贵的新路径。它仍使用原固定 refinement 目标；用户 ε 尚未直接控制该循环，验收核对其实际 state/F-group 差是否满足请求，而不补造新 accuracy 字段。有限时间与稳态分开，10 ms 末点不代表稳态。

弯路已停止：新的输出误差估计支线 fresh 全流程约 **12.80 s**，慢于对应原流程约 **8.70 s**，因此冻结；局部诊断或内核变快不等于任务变快。首次 EXE 的单光超时、四光 REAL 检查失败也曾真实发生，修正后第二候选短时通过。验收器曾误要求主动 capabilities 和所有路径统一 accuracy 字段，现已修正，原失败记录仍保留。

## 实际 EXE 短时结果

完整 32 态、20 μs / 200 点，表内为 fresh worker **进程墙钟秒数**。十二个输入/精度组合均有通过记录；其中 11 项来自当前候选 `f7e24b5e…24d5e`，两光 0.005 沿用首候选的未改动周期路径记录（†），并非在当前二进制重复测试。

| 近光数 | 0.001 | 0.005 | 0.02 |
|---|---:|---:|---:|
| 1 | 0.234 | 0.794 | 0.237 |
| 2（旧周期路径） | 2.331 | 2.250† | 2.338 |
| 3 | 7.881 | 6.377 | 13.607 |
| 4 | 63.586 | 11.201 | 10.893 |

通过表示网格、初态、trace、输出范围及对应经验性收敛契约合格，**不等于严格误差证明**。两光实际独立网格差为 state `5.3874e-8`、F-group `5.8145e-8`，低于三档请求。精度放宽并不保证耗时单调：三光 0.02 此次反而更慢，四光严格档也明显昂贵；这些不足没有被隐藏或重测挑选。

## 资源、长时与未完成项

CPU 是所有线程累积时间；峰值内存为 Windows peak working set，MB 使用十进制，不等于私有提交量。

| 实际 EXE 用例 | Wall / s | CPU / s | 峰值内存 / MB | 结果 |
|---|---:|---:|---:|---|
| 3 光短时 / 0.005 | 6.377 | 7.734 | 221.1 | 通过 |
| 4 光短时 / 0.005 | 11.201 | 19.156 | 443.7 | 通过 |
| 4 光短时 / 0.001 | 63.586 | 80.953 | 1468.3 | 通过，成本较高 |
| 2 光 0–10 ms / 200 点 / 0.005 | 1.085 | 0.969 | 61.1 | 通过，新 core |
| 4 光 0–10 ms / 200 点 / 0.005 | 120.230 | 146.453 | 2577.1 | **超时，未解决** |

四光长时达到观察器 120 s 上限后被终止，没有合格轨迹返回。其后 **1/2 光独立稳态未执行，5 光压力测试未执行**；不能把路径保留说成最终 EXE 已验收。现按用户要求停止 profiling 与追加测试，交付当前结果及明确缺口。

先前同网格实现对照继续有效：四光 0.005，Rust native runner 含准备 **10.8207 s**、CPU **17.2813 s**、峰值 **438.7 MB**；Python 数值流程 **13.7068 s**。最大 state 差 **0.00022995356**、group 差 **0.00021904110**。这是同目标的数值一致性，不是独立高精度真值，本轮未重做参考。

## 交付边界与后续事项

canonical `rust-solver/population-core` 已由桌面 worker 静态链接，复用同一 OpenBLAS 与 v3 widgets。候选单 EXE 为 **15,177,418 B（约 15.18 MB）**，运行使用系统 WebView2，不依赖 Python/QuTiP 或研究 DLL；验收用的 Python 标准库脚本仅是外部测试工具。递归源码/依赖 SHA 随打包校验，无历史模拟答案缓存。本报告不把构建成功等同于全部性能目标完成。

短期确定工程项：后续补齐未测稳态和五光，保留失败/取消提示；将已通过输入纳入回归；核对 UI 层级组布居与精度 scope。四光长时的时间和内存成本是明确待办，不能承诺修复时长。

算法项需重新论证后再推进：真正降低完整任务成本的输出误差估计、含外域残差的连续时间布居误差界，以及多独立拍频轴的长时工作量控制。当前结果不是性能极限，也没有 10 倍或 1 秒保证。

EXE 证据：`artifacts/acceptance/exe-smoke-2/summary.json`、`exe-matrix-2/summary.json`、`exe-long-steady-2/summary.json`；†为 `exe-smoke-1/revalidated-summary.json`，该旧次未请求 capabilities，离线重验明确保留这一测试缺口。原生/Python 对照见 `native-finite-four005-200.json` 及 `same-grid-four005-200-control/comparison.json`。
