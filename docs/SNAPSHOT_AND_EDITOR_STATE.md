# 远端快照、数值编辑与 Scan Plan 状态

## 远端 snapshot

通用 fabric 现在转发设备自身的完整 snapshot，而不是从控制面板拼一份字段较少的替代记录。
本地和远端共用相同的设备实现，包含 values、units、provenance 及设备专用字段。
设备字段与 apparatus 的身份字段冲突时，共享记录路径保留冲突字段，不静默丢弃；
远端连接来源另放在 `apparatus.device_transports`，不覆盖设备自己的字段。

能力位向后兼容：旧发布端没有 snapshot 能力时明确提示需要更新，不伪造数据。
使用端和发布端都需要更新程序，新的采集记录才能保存远端状态。旧 NPZ 中未采集的历史设置不能补造。

配置完成后的快照等待有总时限。普通快照超时不触发 watchdog、SAFE 或夺取 owner；
尚未发送的过期请求会取消，已开始的本地管道写入会完成帧并丢弃迟到结果，每设备最多一项在途。
TCP 已写出部分帧后失败属于真实连接损坏，仍需断开以保护协议；零字节写入超时保留连接。
显式关闭 host 时，超出原有关闭预算才结束本 host 所属的残留进程。

SLM 本机 head 和网络 head 当前使用同一个 adapter，都未提供 采集 snapshot，仍如实显示 unavailable。
Sequencer 已有专用完整 snapshot，未改变。两个记录的 Pulse 入口及其语义均保留。

## 采集记录与 Figure Viewer

Start 不读取整台设备。实际采集源在 arm 和硬件接受参数确认之后、读取循环之前记录设备状态；
扫描先设置首点、加载 Pulse，再启动采集源并复用同一份记录，最后触发。
ready 子采集和父任务共享 context，独立 terminal 采集使用自己的 context。
未显式采集的节点不附加空环境记录，沿用自身与来源事实；不在首份数据提交后补读并冒充之前状态。
停止和结束会解除等候；静态设备仍包含在环境记录中，超时和不支持保留原因。

相同 context 的完整 apparatus 在 NPZ 内只保存一次，由 Rust/Python reader 恢复完整公共结构。
扫描的恢复备份只用于运行内部；首点记录保存实际设置，逐点读数保留硬件量化结果和单位。
Figure Viewer 移除 Raw 标签：Logic 展示 run/event 事实，Plot 展示归档绘图配置，
Devices 以有意义的状态与来源名称替代数组下标，严格相同状态合并来源。
原始文件元数据保持完整，旧文件的启动前记录仍如实标记，不能改称实际采集状态。

## Pulse 文件按钮

对照 v2 `InfoTree._add_action`：使用普通 FluentButton 的高度与内边距，按钮左对齐，
按钮容器位于单元格的内容区，保留上下和左右内边距；按钮保持普通控件高度。
行 hover 覆盖整行，按钮显示自己的 hover。左键点击按钮只执行动作，保留原来的行选择；
点击行名称或按钮外空白才选择该行，与 v2 的嵌入式控件一致。
InfoTree 的行按完整内容高度排布；容器变矮或记录增多时只增加滚动范围，
不压缩行背景和命中区域，文字与按钮始终位于各自行内。
长名称不截断，通过树的横向滚动读取；过滤按按钮可见文字匹配。

## 数值滚轮

共享 SpinBox 按十进制格点计算商、格点和乘积，最后一次转换为 Number，
避免浮点乘除累积及过宽的格点容差。步进后的显示和提交值一致。
DG4000 和通用 tunable 的标量单位转换共用精确前缀转换，step 与 bounds 同步换算。
真实高精度输入、非线性转换和硬件量化回读不做全局四舍五入。

## Scan Plan 缓存

同一节点编辑上下文按完整 port 身份记忆 Range、Values、mode、unit 和步长。
频率→时长→频率会恢复之前编辑的频率配置，普通重绘、读数与运行状态更新不会清空。
节点、Pulse 文件、设备绑定或原生单位契约不同不会串用缓存。
成功 Revert、Load/New/Clear 等明确替换会清理；取消或失败保留。
缓存仅驻留编辑器，不写入最终 scan plan，也不新增持久化文件。

## 联动扫描

Scan Plan 每个轴行末尾的 Link 开关展开同列对齐的联动行，以细分组线表示归属。
Formula 只接受数字、x、括号及 + - * / **；常数直接写入表达式，例如 120-x。
x 是父轴当前显示单位下的数字，结果使用联动行自行选择的单位；切换单位不换算数字或改写公式。
Range 联动项按父轴点数生成，Values 必须等长；关闭 Link 保留输入，但不参与执行、设备声明或 API 覆盖。
同组列逐点配对，不增加数据维度；以 coordinate_of 保存同轴替代坐标。混合设备/API/板上槽的组由主机
推进，板上槽作为每次 FIRE 的表列一起装载；纯板上组仍编译成配对扫描表。恢复设备仍走原来的 cleanup。
联动扫描的点数/shot 数精确，当前时长估计会明确显示未知，不以笛卡尔积错误估算配对表。

Pulse Editor 的 Python Run 负责生成扫描表，On Pulse 执行它。Run repeats=∞ 表示永久停在第一点，
Scan repeats=∞ 才表示整表循环；生成/加载多点表及 On Pulse 时，仍为∞的 Run repeats 明确改为1并显示在草稿中。
有限 Run repeats、单点/无表无限播放、Hold 和 Step 的语义不变。

## 默认交互与范围恢复

Task Console 和 Pulse Preview 的 Selectors 默认开启；用户主动关闭的状态保留。
Image 的完整 home limits 由原始图像范围给出，独立图像与 Facet 内图像使用同一规则；
缩放中的数据更新不能把当前 viewport 记为新的完整范围。
指针消息携带浏览器事件发生时刻，避免中/右键双击识别依赖渲染队列延迟。
Scan Plan 主轴及联动输入在值更新时保留 DOM 身份和焦点，连续滚轮以及小幅滚轮累积不会因重挂载中断。
